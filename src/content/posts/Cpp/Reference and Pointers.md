## 左值引用 (Lvalue references)

在 C++中， <font color="#4dfe50">引用</font>(**reference**)是对现有对象的别名。一旦定义了引用，对引用的任何操作都将应用于被引用的对象。这意味着我们可以使用引用来读取或修改被引用的对象。

> [!NOTE] 洞察
> 引用本质上与被引用的对象是完全相同的。

现代 C++ 包含两种类型的引用：左值引用和右值引用。在本章中，我们将讨论左值引用。

### 左值引用类型 (Lvalue reference types)

<font color="#4dfe50">左值引用</font> (**lvalue reference**) （通常称为“引用”，因为在 C++11 之前只有一种类型的引用）作为现有左值（例如变量）的别名。

就像对象的类型决定了它可以持有什么样的值，引用的类型决定了它可以引用什么类型的对象。左值引用类型可以通过在类型说明符中使用单个与号（&）来识别：

```cpp
// 常规类型
int        // 普通 int 类型（不是引用）
int&       // 指向 int 对象的左值引用
double&    // 指向 double 对象的左值引用
const int& // 指向 const int 对象的左值引用
```

例如，`int&` 是对 `int` 对象的左值引用类型，而 `const int&` 是对 `const int` 对象的左值引用类型。

#### 通过非常量左值引用修改值

我们可以使用非常量引用来修改被引用对象的值：

```cpp
#include <iostream>

int main()
{
    int x { 5 }; // 普通整数变量
    int& ref { x }; // ref 现在是变量 x 的别名

    std::cout << x << ref << '\n'; // 打印 55

    x = 6; // x 现在为 6

    std::cout << x << ref << '\n'; // 打印 66

    ref = 7; // 被引用对象（x）现在为 7

    std::cout << x << ref << '\n'; // 打印 77

    return 0;
}
```

此代码输出：
<pre>
55
66
77
</pre>

在上述示例中，`ref` 是 `x` 的别名，因此我们可以通过 `x` 或 `ref` 来改变 `x` 的值。

#### 引用初始化

与常量类似，所有引用必须被初始化。引用通过一种称为<font color="#4dfe50">引用初始化</font>(**reference initialization**)的形式进行初始化。

```cpp
int main()
{
    int& invalidRef;   // 错误：引用必须初始化

    int x { 5 };
    int& ref { x }; // 正确：指向 int 的引用绑定到 int 变量

    return 0;
}
```

当一个引用被初始化为一个对象（或函数）时，我们称它与该对象（或函数）<font color="#4dfe50">绑定</font>(**bound**) 。这种引用绑定的过程称为<font color="#4dfe50">引用绑定</font>(**reference binding**)。被引用的对象（或函数）有时被称为<font color="#4dfe50">被引用对象</font>(**referent**) 。

非常量左值引用只能绑定到一个*可修改*的左值。

```cpp
int main()
{
    int x { 5 };
    int& ref { x };         // 正确：非常量左值引用绑定到可修改左值

    const int y { 5 };
    int& invalidRef { y };  // 错误：非常量左值引用不能绑定到不可修改左值
    int& invalidRef2 { 0 }; // 错误：非常量左值引用不能绑定到右值

    return 0;
}
```

#### 引用（通常）只会绑定到与其引用类型匹配的对象上。

在大多数情况下，引用只会绑定到与引用类型匹配的对象（对于这个规则有一些例外，我们将在讨论继承时提到这些例外）。

如果你尝试将引用绑定到与其引用类型不匹配的对象，编译器会尝试将该对象隐式转换为引用类型，然后将引用绑定到该对象。

> [!TIP] 绑定在不匹配的对象上可能会导致编译错误
> 如果转换的结果是一个右值，而非常量左值引用不能绑定到右值，因此尝试将非常量左值引用绑定到与其引用类型不匹配的对象将导致编译错误。

```cpp
int main()
{
    int x { 5 };
    int& ref { x };            // 正确：引用类型（int）与初始化值类型匹配

    double d { 6.0 };
    int& invalidRef { d };     // 错误：double 到 int 的转换是窄化转换，列表初始化不允许
    double& invalidRef2 { x }; // 错误：非常量左值引用不能绑定到右值（x 转为 double 的结果）

    return 0;
}
```

#### 引用不能被重新设置（更改为指向另一个对象）

一旦初始化，C++ 中的引用不能被**重新赋值** ，这意味着它不能被更改为引用另一个对象。

新的 C++ 程序员经常尝试通过赋值来重新赋值引用，以便让引用指向另一个变量。这将编译并运行——但不会按预期功能工作。考虑以下程序：

```cpp
#include <iostream>

int main()
{
    int x { 5 };
    int y { 6 };

    int& ref { x }; // ref 现在是 x 的别名

    ref = y; // 将 6（y 的值）赋给 x（ref 引用的对象）
    // 上面这一行并不会把 ref 变成对 y 的引用！

    std::cout << x << '\n'; // 用户可能期望这里输出 5

    return 0;
}
```

也许令人惊讶的是，这将输出：
<pre>
6
</pre>
当引用在表达式中被求值时，它解析为它所引用的对象。因此，`ref = y` 并不会将 `ref` 更改为现在引用 `y`。相反，由于 `ref` 是 `x` 的别名，该表达式的求值就像是写成 `x = y` -- 而且由于 `y` 的值为 `6`，所以 `x` 被赋值为 `6`。

### 对常量的左值引用

考虑以下程序:

```cpp
int main()
{
    const int x { 5 }; // x 是不可修改的（const）左值
    int& ref { x }; // 错误：ref 不能绑定到不可修改左值

    return 0;
}
```

这是不允许的，因为这将允许我们通过非常量引用（`ref`）修改一个常量变量（`x`）。

但是如果我们想要一个常量变量并创建一个引用呢？普通的左值引用（指向非常量值）是行不通的。

#### 对常量的左值引用

通过在声明左值引用时使用 `const` 关键字，我们告诉左值引用将其引用的对象视为常量。这样的引用称为 **对常量值的左值引用** （有时称为 **对常量的引用** 或 **常量引用** ）。

对常量的左值引用可以绑定到不可修改的左值：

```cpp
int main()
{
    const int x { 5 };    // x 是不可修改的左值
    const int& ref { x }; // 正确：ref 是指向常量值的左值引用

    return 0;
}
```

因为对常量的左值引用将它们引用的对象视为 const，所以它们可以用于访问但不能修改被引用的值：

```cpp
#include <iostream>

int main()
{
    const int x { 5 };    // x 是不可修改的左值
    const int& ref { x }; // 正确：ref 是指向常量值的左值引用

    std::cout << ref << '\n'; // 正确：可以访问常量对象
    ref = 6;                  // 错误：不能通过常量引用修改对象

    return 0;
}
```

#### 用可修改的左值初始化对常量的左值引用

对常量的左值引用也可以绑定到可修改的左值。在这种情况下，通过引用访问时，被引用的对象被视为常量（尽管底层对象是非常量的）：

```cpp
#include <iostream>

int main()
{
    int x { 5 };          // x 是可修改的左值
    const int& ref { x }; // 正确：可以将常量引用绑定到可修改左值

    std::cout << ref << '\n'; // 正确：可以通过常量引用访问对象
    ref = 7;                  // 错误：不能通过常量引用修改对象

    x = 6;                // 正确：x 是可修改左值，仍可通过原始标识符修改

    return 0;
}
```

在上面的程序中，我们将常量引用 `ref` 绑定到可修改的左值 `x`。然后我们可以使用 `ref` 访问 `x`，但由于 `ref` 是常量引用，我们不能通过 `ref` 修改 `x` 的值。然而，我们仍然可以直接修改 `x` 的值（使用标识符 `x`）。

> [!SUCCESS] 对常量的左值引用的最佳实践
> 除非需要修改被引用的对象，否则优先使用 `常量的左值引用` 而不是 `非常量的左值引用` 。

#### 用右值初始化常量的左值引用

或许令人惊讶的是，指向常量的左值引用也可以绑定到右值：

```cpp
#include <iostream>

int main()
{
    const int& ref { 5 }; // 正确：5 是右值

    std::cout << ref << '\n'; // 打印 5

    return 0;
}
```

当这种情况发生时，会创建一个临时对象并用右值初始化，并且指向常量的引用绑定到该临时对象。

#### 用不同类型的值初始化指向常量的左值引用

常量左值引用甚至可以绑定到不同类型的值，只要这些值可以隐式转换为引用类型：

```cpp
#include <iostream>

int main()
{
    // 情况 1
    const double& r1 { 5 };  // 临时 double 以 5 初始化，r1 绑定到临时对象

    std::cout << r1 << '\n'; // 打印 5

    // 情况 2
    char c { 'a' };
    const int& r2 { c };     // 临时 int 以 'a' 初始化，r2 绑定到临时对象

    std::cout << r2 << '\n'; // 打印 97（因为 r2 是 int 的引用）

    return 0;
}
```

在情况 1 中，创建了一个类型为 `double` 的临时对象，并用 int 值 `5` 对其进行初始化。然后 `const double& r1` 绑定到该临时的 double 对象。

在情况 2 中，创建了一个类型为 `int` 的临时对象，并用 char 值 `a` 进行初始化。然后 `const int& r2` 绑定到那个临时的 int 对象。

另请注意，当我们打印 `r2` 时，它是以 int 类型而非 char 类型打印的。这是因为 `r2` 是一个 int 对象的引用（即创建的临时 int），而不是 char `c` 的引用。

#### 绑定到临时对象的常量引用会延长临时对象的生命周期

临时对象通常在创建它们的表达式结束时被销毁。

给定语句 `const int& ref { 5 };` ，考虑如果用于保存右值 `5` 的临时对象在初始化 `ref` 的表达式结束时被销毁，会发生什么情况。引用 `ref` 将会悬空（引用一个已被销毁的对象），当我们尝试访问 `ref` 时，将会导致未定义行为。

为了避免在这种情况下出现悬空引用，C++有一条特殊规则：当常量左值引用直接绑定到临时对象时，该临时对象的生命周期会被延长，以匹配引用的生命周期。

```cpp
#include <iostream>

int main()
{
    const int& ref { 5 }; // 持有 5 的临时对象生命周期被延长到与 ref 一致

    std::cout << ref << '\n'; // 因此可以安全使用

    return 0;
} // ref 与临时对象在此处一起销毁
```

在上面的例子中，当 `ref` 用右值 `5` 初始化时，会创建一个临时对象， `ref` 绑定到该临时对象。临时对象的生命周期与 `ref` 的生命周期相匹配。因此，我们可以在下一条语句中安全地打印 `ref` 的值。然后 `ref` 和临时对象都会离开作用域，并在代码块结束时被销毁。

### 左值引用传递

当我们调用函数时，我们只是复制了参数的值，然后再短暂地使用它，然后再销毁它！幸运的是，由于基本类型复制很便宜，这并不是一个问题。

#### 一些对象复制很昂贵

标准库提供的大多数类型（如 `std::string`）都是类类型。类类型通常昂贵地复制。在可能的情况下，我们希望避免对昂贵复制的对象进行不必要的复制，尤其是当我们将几乎立即销毁这些复制时。

考虑以下程序来说明这一点：
```cpp
#include <iostream>
#include <string>

void printValue(std::string y)
{
    std::cout << y << '\n';
} // y 在此处销毁

int main()
{
    std::string x { "Hello, world!" }; // x 是 std::string

    printValue(x); // x 按值传递给参数 y（会复制，成本高）

    return 0;
}
```

这将输出:
<pre>
Hello, world!
</pre>

虽然这个程序的行为符合我们的预期，但它也是不高效的。与之前的例子一样，当调用 `printValue()` 时，参数 `x` 被复制到 `printValue()` 的参数 `y` 中。然而，在这个例子中，参数是一个 `std::string` 而不是一个 `int`，而 `std::string` 是一个昂贵的类类型，每次调用 `printValue()` 时都会进行昂贵的复制。而且，每次调用 `printValue()` 时都会进行一次昂贵的复制！

我们可以做得更好。

#### 引用传递

在调用函数时，避免昂贵地复制参数的一种方法是使用“引用传递”而不是“值传递”。当使用“引用传递”时，我们将函数参数声明为引用类型（或常量引用类型）而不是普通类型。当函数被调用时，每个引用参数都被绑定到相应的参数。由于引用作为参数的别名，不会进行参数的复制。

这是上面例子的相同内容，使用引用传递而不是值传递：
```cpp
#include <iostream>
#include <string>

void printValue(std::string& y) // 类型改为 std::string&
{
    std::cout << y << '\n';
} // y 在此处销毁

int main()
{
    std::string x { "Hello, world!" };

    printValue(x); // x 通过引用传递给参数 y（成本低）

    return 0;
}
```

> [!NOTE] 洞察
> 引用传递避免在函数调用时每次都复制参数。

以下程序演示了值参数与实参是独立的对象，而引用参数则被视为实参本身。
```cpp
#include <iostream>

void printAddresses(int val, int& ref)
{
    std::cout << "值参数的地址是: " << &val << '\n';
    std::cout << "引用参数的地址是: " << &ref << '\n';
}

int main()
{
    int x { 5 };
    std::cout << "x 的地址是: " << &x << '\n';
    printAddresses(x, x);

    return 0;
}
```

上面程序的运行结果如下:
<pre>
x 的地址是: 0x7ffd16574de0
值参数的地址是: 0x7ffd16574de4
引用参数的地址是: 0x7ffd16574de0
</pre>

我们可以看到，参数的地址与值参数不同，这意味着值参数是一个不同的对象。由于它们具有不同的内存地址，为了使值参数的值与参数相同，必须将参数的值复制到值参数所持有的内存中。

另一方面，我们可以看到，取引用参数的地址与参数的地址相同。这意味着引用参数被当作与参数相同的对象来处理。

#### 引用传递允许修改实参的值

当一个对象使用值传递时，函数参数接收的是实参的副本。这意味着对形参值进行的任何更改都会反映在副本上，而不是实参本身。
```cpp
#include <iostream>

void addOne(int y) // y 是 x 的副本
{
    ++y; // 只修改副本，而非实际对象 x
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x 未被修改

    return 0;
}
```

在上面的程序中，因为值参数 `y` 是 `x` 的副本，当我们递增 `y` 时，这只会影响到 `y`。这个程序输出：
<pre>
value = 5
value = 5
</pre>

然而，由于引用与被引用的对象具有相同的行为，当使用引用传递时，对引用参数的任何更改都会影响实参。
```cpp
#include <iostream>

void addOne(int& y) // y 绑定到实际对象 x
{
    ++y; // 修改实际对象 x
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x 已被修改

    return 0;
}
```

这个程序将输出:
<pre>
value = 5
value = 6
</pre>

在上面的示例中，`x` 的初始值为 `5`。当调用 `addOne(x)` 时，引用参数 `y` 被绑定到实参 `x`。当 `addOne()` 函数递增引用 `y` 时，实际上是递增实参 `x` 从 `5` 到 `6`（而不是 `x` 的副本）。即使 `addOne()` 执行完毕，这个值仍然保持不变。

函数修改传入实参值的能力是有用的。想象一下，你编写了一个函数，可以确定怪物是否成功攻击了玩家。如果成功，怪物应该对玩家的生命值造成一定的伤害。如果你使用引用传递玩家对象，函数可以直接修改传入的实际玩家对象的生命值。如果你使用值传递玩家对象，你只能修改玩家对象的副本的生命值，这不太实用。

#### 引用传递仅接受可修改的左值参数

由于非常量引用只能绑定到可修改的左值（基本上是非常量变量），这意味着仅引用传递只能与可修改的左值参数一起使用。在实际操作中，这显著限制了使用非常量引用传递的有用性，因为这意味着我们不能传递常量变量或字面量。例如：
```cpp
#include <iostream>

void printValue(int& y) // y 仅接受可修改左值
{
    std::cout << y << '\n';
}

int main()
{
    int x { 5 };
    printValue(x); // 正确：x 是可修改左值

    const int z { 5 };
    printValue(z); // 错误：z 是不可修改左值

    printValue(5); // 错误：5 是右值

    return 0;
}
```

### 常量左值引用传递

与非常量引用（只能绑定到可修改的左值）不同，常量的引用可以绑定到可修改的左值、不可修改的左值和右值。因此，如果我们使引用参数为常量，那么它将能够绑定到任何类型的参数：
```cpp
#include <iostream>

void printRef(const int& y) // y 是常量引用
{
    std::cout << y << '\n';
}

int main()
{
    int x { 5 };
    printRef(x);   // 正确：x 是可修改左值，y 绑定到 x

    const int z { 5 };
    printRef(z);   // 正确：z 是不可修改左值，y 绑定到 z

    printRef(5);   // 正确：5 是右值字面量，y 绑定到临时 int 对象

    return 0;
}
```

通过常量引用传递与通过非常量引用传递具有相同的主要优势（避免复制参数），同时保证函数不能改变所引用的值。

例如，以下是不允许的，因为 `ref` 是常量引用：
```cpp
void addOne(const int& ref)
{
    ++ref; // 错误：ref 是常量引用
}
```

在大多数情况下，我们不想让函数修改参数的值。

> [!SUCCESS] 最佳实践
> 除非你有特定的理由要这样做（例如，函数需要改变参数的值），否则优先使用（常量）引用传递而非非常量引用传递。

现在我们可以理解允许对常量的左值引用绑定到右值的原因：如果没有这种能力，将没有任何方法将字面量（或其他右值）传递给使用引用传递的函数！

#### 将不同类型的参数传递给常量左值引用参数

上文中，我们提到，只要该值可以转换为引用的类型，常量的左值引用可以绑定到不同类型的值。这种转换会创建一个临时对象，然后引用参数可以绑定到该对象。

允许这样做的主要动机是，我们可以以完全相同的方式将一个值作为参数传递给值参数或常量的引用参数：
```cpp
#include <iostream>

void printVal(double d)
{
    std::cout << d << '\n';
}

void printRef(const double& d)
{
    std::cout << d << '\n';
}

int main()
{
    printVal(5); // 5 转换为临时 double，复制到参数 d
    printRef(5); // 5 转换为临时 double，绑定到参数 d

    return 0;
}
```

使用值传递时，我们预期会创建一个副本，所以如果先发生转换（导致额外创建一个副本），这通常不是问题（编译器可能会消除这两个副本中的其中一个）。

然而，当我们不希望创建副本时，通常使用引用传递。如果先发生转换，这通常会创建一个（可能昂贵的）副本，这可能不是最优的。

#### 混合值传递与引用传递

一个具有多个参数的函数可以单独确定每个参数是使用值传递还是引用传递。

例如:
```cpp
#include <string>

void foo(int a, int& b, const std::string& c)
{
}

int main()
{
    int x { 5 };
    const std::string s { "Hello, world!" };

    foo(5, x, s);

    return 0;
}
```

在上述示例中，第一个参数使用值传递，第二个使用引用传递，第三个使用常量引用传递。

#### 何时使用值传递与引用传递

对于大多数 C++初学者来说，选择使用值传递还是引用传递并不是很明确。幸运的是，有一个简单实用的经验法则，在大多数情况下都能帮到你。

- 基本类型和枚举类型复制成本低，因此通常使用值传递。
- 类类型复制成本可能很高（有时差异很大），因此通常使用常量引用传递。

> [!SUCCESS] 最佳实践
> 一般来说，基本类型使用值传递，类类型使用常量引用传递。
> 如果你不确定该怎么做，可以使用常量引用传递，这样不太可能遇到意外的行为。

> [!CITE] 以下是一些其他有趣的情况的部分列表：
> 以下通常使用值传递（因为它更高效）：
> 1. 枚举类型（无作用域枚举和作用域枚举）。
> 2. 视图和跨度（例如 `std::string_view` , `std::span` ）。
> 3. 模仿引用或（非拥有型）指针的类型（例如迭代器、 `std::reference_wrapper` ）。
> 4. 具有值语义且复制成本低的类类型（例如 `std::pair` ，其元素为基本类型、 `std::optional` 、 `std::expected` ）。
>    
> 以下情况应使用引用传递：
> 1. 需要被函数修改的实参。
> 2. 不可复制类型（例如 `std::ostream` ）。
> 3. 那些复制具有所有权影响且我们希望避免的类型（例如 `std::unique_ptr` 、 `std::shared_ptr` ）。
> 4. 具有虚函数或可能被继承的类型。

#### 值传递与引用传递的成本对比 ==高级==

并非所有类类型都需要使用引用传递（例如 `std::string_view` 通常使用值传递）。你可能想知道我们为什么不干脆所有东西都使用引用传递。在本节（可选阅读内容）中，我们讨论值传递与引用传递的成本，并完善我们何时应使用每种方式的最佳实践。

首先，我们需要考虑初始化函数参数的成本。使用值传递时，初始化意味着创建一个副本。复制一个对象的成本通常与两件事成正比：
- 对象的大小。使用更多内存的对象复制时需要更多时间。
- 额外的设置成本。某些类类型在实例化时会进行额外的设置（例如打开文件或数据库，或为存储可变大小的对象分配一定量的动态内存）。这些设置成本每次复制对象时都必须支付。

另一方面，将引用绑定到对象总是很快（与复制基本类型的速度大致相同）。

其次，我们需要考虑使用函数参数的成本。在设置函数调用时，编译器可能会通过将值传递的参数（如果它的大小较小）的一个引用或副本放入 CPU 寄存器（访问速度快）而不是 RAM（访问速度慢）来进行优化。

每次使用值参数时，运行程序可以直接访问复制的实参的存储位置（CPU 寄存器或 RAM）。然而，当使用引用参数时，通常需要额外的一步。运行程序必须首先直接访问分配给引用的存储位置（CPU 寄存器或 RAM），以确定正在引用哪个对象。只有到那时，它才能访问被引用对象的存储位置（在 RAM 中）。

因此，每个值参数的使用都是一个 CPU 寄存器或 RAM 访问，而每个引用参数的使用是一个 CPU 寄存器或 RAM 访问加上第二次 RAM 访问。

第三，编译器有时可以比使用引用传递的代码更有效地优化使用值传递的代码。特别是，当存在别名（当两个或多个指针或引用可以访问同一个对象）的可能性时，优化器必须保持保守。由于值传递会导致参数值的复制，因此没有别名发生的可能性，这使得优化器可以更加激进。

现在我们可以回答为什么我们不使用引用传递所有内容的问题：
- 对于复制成本较低的对象，复制成本与绑定成本相似，但访问对象更快，编译器也可能进行更好的优化。
- 对于复制成本较高的对象，复制成本会主导其他性能考虑因素。

那么最后一个问题是，我们如何定义“复制成本较低”？这里没有绝对答案，因为这因编译器、使用场景和架构而异。然而，我们可以制定一个经验法则：如果一个对象的大小不超过两个“机器字”（Machine Word，每个字约等于一个内存地址的大小），且没有额外的设置成本，那么它就是复制成本较低的。

#### 对于函数参数，在大多数情况下优先选择 `std::string_view` 而不是 `const std::string&`

现代 C++中经常出现的一个问题：在编写一个带有字符串参数的函数时，参数的类型应该是 `const std::string&` 还是 `std::string_view` ？

在大多数情况下， `std::string_view` 是更好的选择，因为它可以更高效地处理更广泛的参数类型。一个 `std::string_view` 参数还允许调用者直接传递一个子字符串，而无需先将其复制到自己的字符串中。

在某些情况下，使用 `const std::string&` 参数可能更合适：
- 如果你使用的是 C++14 或更早版本， `std::string_view` 是不可用的。
- 如果你的函数需要调用其他接受 C 风格字符串或 `std::string` 参数的函数，那么 `const std::string&` 可能是更好的选择，因为 `std::string_view` 不保证是空字符终止的（C 风格字符串函数所期望的），并且不能高效地转换回 `std::string` 。

## 指针(Pointers)

### 指针简介
指针是 C++历史上的一个难题，也是许多渴望学习 C++的人卡住的地方。然而，正如你很快就会看到的，指针并没有什么可怕的。

事实上，指针的行为与左值引用非常相似。但在我们进一步解释之前，让我们先做一些准备工作。

考虑一个普通变量，比如这个：
```cpp
char x {}; // char 占用 1 字节内存
```

简化来说，当为这个定义生成代码并执行时，RAM 中的一块内存将被分配给这个对象。为了举例说明，假设变量 `x` 被分配了内存地址 `140` 。每当我们在一个表达式或语句中使用变量 `x` 时，程序会去内存地址 `140` 访问存储在那里的值。

变量的好处在于我们不需要担心分配了什么具体的内存地址，或者需要多少字节来存储对象的值。我们只需通过其给定的标识符来引用变量，编译器会将这个名字翻译成适当分配的内存地址。编译器负责处理所有的寻址。

引用也是如此：
```cpp
int main()
{
    char x {}; // 假设该变量被分配到地址 140
    char& ref { x }; // ref 是对 x 的左值引用（在类型中，& 表示左值引用）

    return 0;
}
```

因为 `ref` 作为 `x` 的别名，每当我们使用 `ref` 时，程序就会去内存地址 `140` 访问该值。编译器会负责处理寻址，所以我们无需考虑这一点。

#### 取地址运算符(&)

虽然变量的内存地址默认情况下不会暴露给我们，但我们确实可以访问这些信息。取地址运算符(&)返回其操作数的内存地址。这非常直接：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    std::cout << x << '\n';  // 打印变量 x 的值
    std::cout << &x << '\n'; // 打印变量 x 的内存地址

    return 0;
}
```

在作者机器上，上述程序打印了：
<pre>
5
0027FEA0
</pre>
在上述示例中，我们使用取地址运算符（&）来获取变量 `x` 分配的地址，并将该地址打印到控制台。内存地址通常以十六进制值的形式打印。

对于使用超过一个字节的内存的对象，取地址运算符将返回对象使用的第一个字节的内存地址。

> [!TIP] &符号容易引起混淆，因为它在不同的上下文中具有不同的含义：
> - 当跟在类型名称后面时，&表示左值引用： `int& ref` 。
> - 当在表达式中的单目上下文中使用时，&是取地址运算符： `std::cout << &x` 。
> - 当在表达式中的双目上下文中使用时，&是按位与运算符： `std::cout << x & y` 。

#### 解引用运算符（\*）

仅获取变量的地址本身并不是很有用。

我们能对一个地址做的最有用的事情是访问存储在该地址的值。<font color="#4dfe50">解引用运算符</font>(**dereference operator**)（\*）（有时也称为间接引用运算符）将给定内存地址处的值作为左值返回：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    std::cout << x << '\n';  // 打印变量 x 的值
    std::cout << &x << '\n'; // 打印变量 x 的内存地址

    std::cout << *(&x) << '\n'; // 打印变量 x 所在地址的值（加括号便于阅读）

    return 0;
}
```

这个程序相当简单。首先我们声明一个变量 `x` 并打印它的值。然后我们打印变量 `x` 的地址。最后，我们使用解引用运算符来获取变量 `x` 内存地址处的值（这其实就是 `x` 的值），并将其打印到控制台。

> [!NOTE] 关键洞察
> 给定一个内存地址，我们可以使用解引用运算符（*）来获取该地址处的值（作为一个左值）。
> 取地址运算符（&）和解引用运算符（\*）的作用是相反的：取地址运算符获取对象的地址，而解引用运算符获取地址处的对象。

> [!TIP] 关于解引用运算符和乘法运算符
> 尽管解引用运算符看起来和乘法运算符一样，但你能够区分它们，因为解引用运算符是一元的，而乘法运算符是二元的。

获取一个变量的内存地址，然后立即对该地址进行解引用以获取值也并不那么有用（毕竟，我们直接使用变量就可以访问该值）。

但现在我们有了取地址运算符(&)和解引用运算符(\*)，我们就可以开始讨论指针了。

#### 指针

指针是一个对象，它的值是一个内存地址（通常是另一个变量的地址）。这使得我们可以存储某个其他对象的地址，以便稍后使用。

指定指针的类型（例如 `int*` ）称为指针类型。就像引用类型使用与号（&）字符声明一样，指针类型使用星号（*）声明：
```cpp
int;  // 普通 int
int&; // 一个对 int 类型的左值引用

int*; // 一个对 int 指的指针
```

请注意，这个星号是指针声明语法的一部分，而不是解引用运算符的使用。

> [!SUCCESS] 最佳实践
> 在声明指针类型时，将星号放在类型名称旁边。

#### 指针初始化

和普通变量一样，指针默认情况下不会被初始化。未初始化的指针有时被称为野指针。野指针包含一个垃圾地址，解引用野指针会导致未定义行为。因此，你应该总是将指针初始化为一个已知的值。

> [!SUCCESS] 最佳实践
> 始终初始化你的指针。

```cpp
int main()
{
    int x{ 5 };

    int* ptr;        // 未初始化指针（持有垃圾地址）
    int* ptr2{};     // 空指针（下一节会讨论）
    int* ptr3{ &x }; // 使用变量 x 的地址初始化指针

    return 0;
}
```

由于指针存储地址，当我们初始化或为指针赋值时，该值必须是地址。通常，指针用于存储另一个变量的地址（我们可以使用取地址运算符(&)获取该地址）。

一旦我们有一个指向另一个对象的指针，我们就可以使用解引用运算符（\*）来访问该地址处的值。例如：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    std::cout << x << '\n'; // 打印变量 x 的值

    int* ptr{ &x }; // ptr 持有 x 的地址
    std::cout << *ptr << '\n'; // 解引用 ptr，打印其地址处的值（即 x 的值）

    return 0;
}
```

这将会输出:
<pre>
5
5
</pre>

这就是指针得名的由来—— `ptr` 持有 `x` 的地址，所以我们说 `ptr` “指向” `x` 。

> [!NOTE] 注释
> 关于指针的命名规则： “X 指针”（其中 X 是某种类型）是“指向 X 的指针”的常用缩写。因此，当我们说“一个整数指针”时，实际上是指“指向整数的指针”。这种理解在讨论常量指针时将非常有价值。

就像引用的类型必须与所引用的对象的类型相匹配一样，指针的类型也必须与所指向的对象的类型相匹配：
```cpp
int main()
{
    int i{ 5 };
    double d{ 7.0 };

    int* iPtr{ &i };     // 正确：指向 int 的指针可以指向 int 对象
    int* iPtr2 { &d };   // 错误：指向 int 的指针不能指向 double 对象
    double* dPtr{ &d };  // 正确：指向 double 的指针可以指向 double 对象
    double* dPtr2{ &i }; // 错误：指向 double 的指针不能指向 int 对象

    return 0;
}
```

除下一节我们将讨论的一个例外外，使用字面量初始化指针是不允许的：
```cpp
int* ptr{ 5 }; // 错误
int* ptr{ 0x0012FF7C }; // 错误：0x0012FF7C 会被视为整数字面量
```

#### 指针和赋值

我们可以用两种不同的方式使用指针的赋值：
- 改变指针指向的对象（通过给指针赋一个新的地址）
- 改变被指向的值（通过给解引用的指针赋一个新的值）

首先，让我们看一个指针被改变以指向不同对象的例子：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // ptr 初始化为指向 x

    std::cout << *ptr << '\n'; // 打印指针所指地址的值（x 的地址）

    int y{ 6 };
    ptr = &y; // 将 ptr 改为指向 y

    std::cout << *ptr << '\n'; // 打印指针所指地址的值（y 的地址）

    return 0;
} 
```

上面的例子输入:
<pre>
5
6
</pre>

在上述示例中，我们定义了指针 `ptr` ，用 `x` 的地址初始化它，并通过解引用指针来打印所指向的值（ `5` ）。然后我们使用赋值运算符将 `ptr` 所持有的地址改为 `y` 的地址。接着我们再次解引用指针来打印所指向的值（现在是 `6` ）。

现在让我们看看我们还可以如何使用指针来改变所指向的值：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // 使用变量 x 的地址初始化 ptr

    std::cout << x << '\n';    // 打印 x 的值
    std::cout << *ptr << '\n'; // 打印 ptr 所持地址的值（x 的地址）

    *ptr = 6; // 将 ptr 所持地址处的对象（x）赋值为 6（此处对 ptr 解引用）

    std::cout << x << '\n';
    std::cout << *ptr << '\n'; // 打印 ptr 所持地址的值（x 的地址）

    return 0;
}
```

这个程序输出:
<pre>
5
5
6
6
</pre>

在这个例子中，我们定义了指针 `ptr` ，用 `x` 的地址初始化它，然后打印 `x` 和 `*ptr` （ `5` ）的值。因为 `*ptr` 返回一个左值，我们可以把它用在赋值语句的左侧，我们用它来改变 `ptr` 所指向的值为 `6` 。然后我们再次打印 `x` 和 `*ptr` 的值，以显示值已经按预期更新。

> [!NOTE] 洞察
> 当我们使用一个没有解引用的指针（ `ptr` ）时，我们访问的是指针所持有的地址。修改这个（ `ptr = &y` ）会改变指针所指向的内容。
> 当我们解引用一个指针（ `*ptr` ）时，我们正在访问被指向的对象。修改这个（ `*ptr = 6;` ）会改变被指向对象的值。

#### 指针的行为与左值引用非常相似

指针和左值引用的行为相似。考虑以下程序：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    int& ref { x };  // 获取对 x 的引用
    int* ptr { &x }; // 获取指向 x 的指针

    std::cout << x;
    std::cout << ref;  // 使用引用打印 x 的值（5）
    std::cout << *ptr << '\n'; // 使用指针打印 x 的值（5）

    ref = 6; // 使用引用修改 x 的值
    std::cout << x;
    std::cout << ref;  // 使用引用打印 x 的值（6）
    std::cout << *ptr << '\n'; // 使用指针打印 x 的值（6）

    *ptr = 7; // 使用指针修改 x 的值
    std::cout << x;
    std::cout << ref;  // 使用引用打印 x 的值（7）
    std::cout << *ptr << '\n'; // 使用指针打印 x 的值（7）

    return 0;
}
```

在上述程序中，我们创建了一个普通变量 `x` ，其值为 `5` ，然后创建了一个左值引用和一个指向 `x` 的指针。接下来，我们使用左值引用将值从 `5` 更改为 `6` ，并展示我们可以通过所有三种方法访问该更新后的值。最后，我们使用解引用的指针将值从 `6` 更改为 `7` ，再次展示我们可以通过所有三种方法访问更新后的值。

因此，指针和引用都提供了一种间接访问另一个对象的方法。主要区别在于，使用指针时，我们需要显式获取要指向的地址，并且必须显式解引用指针以获取值。而使用引用时，地址取值和解引用是隐式发生的。

指针和引用之间还有一些其他值得提及的区别：
- 引用必须初始化，而指针不需要初始化（但应该初始化）。
- 引用不是对象，指针是。
- 引用不能被重新绑定（改变为引用其他事物），指针可以改变它们所指向的内容。
- 引用必须始终绑定到一个对象，指针可以指向空（我们将在下一节看到一个例子）。
- 引用是“安全”的（除了悬空引用之外），指针本质上是有风险的（我们将在下一课中也讨论这一点）。

#### 取地址运算符返回一个指针

值得注意的是，取地址运算符（&）并不返回其操作数的地址作为字面量（因为 C++不支持地址字面量）。相反，它返回一个指向操作数的指针（其值是操作数的地址）。换句话说，给定变量 `int x` ， `&x` 返回一个 `int*` 持有 `x` 的地址。

我们可以在以下示例中看到这一点：
```cpp
#include <iostream>
#include <typeinfo>

int main()
{
	int x{ 4 };
    std::cout << typeid(x).name() << '\n';  // 打印 x 的类型
    std::cout << typeid(&x).name() << '\n'; // 打印 &x 的类型

	return 0;
}
```

在 Visual Studio 上，这输出了：
<pre>
int
int *
</pre>

使用 gcc，这打印了 `i` (int) 和 `pi` (指向 int 的指针)。因为 typeid().name() 的结果是依赖于编译器的，你的编译器可能会打印出不同的内容，但它会有相同的意义。

#### 指针的大小

指针的大小取决于可执行文件所编译的架构——32 位可执行文件使用 32 位内存地址——因此，在 32 位机器上的指针是 32 位（4 字节）。对于 64 位可执行文件，指针将是 64 位（8 字节）。请注意，这适用于所指向对象的大小，无论对象的大小如何：
```cpp
#include <iostream>

int main() // 假设是 32 位应用
{
    char* chPtr{};        // char 通常是 1 字节
    int* iPtr{};          // int 通常是 4 字节
    long double* ldPtr{}; // long double 通常是 8 或 12 字节

    std::cout << sizeof(chPtr) << '\n'; // 打印 4
    std::cout << sizeof(iPtr) << '\n';  // 打印 4
    std::cout << sizeof(ldPtr) << '\n'; // 打印 4

    return 0;
}
```

指针的大小始终相同。这是因为指针只是一个内存地址，而访问一个内存地址所需的位数是固定的。

#### 悬空指针

与悬空引用类似，<font color="#4dfe50">悬空指针</font>(**dangling pointer**)是指向一个不再有效的对象地址的指针（例如，因为它已被销毁）。

对悬空指针进行解引用（例如，为了打印它所指向的值）会导致未定义行为，因为你试图访问一个不再有效的对象。

或许令人惊讶的是，标准规定“任何其他使用无效指针值的行为是未定义的”。这意味着你可以给无效指针赋予一个新值，例如 nullptr（因为这不使用无效指针的值）。然而，任何其他使用无效指针值的行为（例如复制或递增无效指针）都会产生未定义行为。

> [!NOTE] 洞察
> 解引用一个无效指针会导致未定义行为。而对无效指针值的任何其他使用方式，则是由实现定义的。

这里是一个创建悬空指针的例子：
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    int* ptr{ &x };

    std::cout << *ptr << '\n'; // 有效

    {
        int y{ 6 };
        ptr = &y;

        std::cout << *ptr << '\n'; // 有效
    } // y 离开作用域，ptr 成为悬空指针

    std::cout << *ptr << '\n'; // 解引用悬空指针导致未定义行为

    return 0;
}
```

上述程序可能会输出：
<pre>
5
6
6
</pre>

但它可能不会，因为 `ptr` 所指向的对象在内部块的末尾超出了作用域并被销毁，留下了悬空的 `ptr` 。

#### 结论

指针是存储内存地址的变量。它们可以使用解引用运算符（\*）来解引用，以获取它们所持有的地址处的值。解引用一个野指针或悬空指针（或空指针）将导致未定义行为，并可能使您的应用程序崩溃。

指针比引用更灵活，但也更危险。我们将继续探讨这一点。

### 空指针

在上一节（[[#指针简介]]）中，我们介绍了指针的基础知识，指针是持有另一个对象地址的对象。可以使用解引用运算符（\*）来解引用这个地址，从而获取该地址处的对象：

```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    std::cout << x << '\n'; // 打印变量 x 的值

    int* ptr{ &x }; // ptr 持有 x 的地址
    std::cout << *ptr << '\n'; // 解引用 ptr 打印其地址处的值（即 x 的地址处）

    return 0;
}
```

上述示例输出：
<pre>
5
5
</pre>

在上一课中，我们还注意到指针不必指向任何东西。在本课中，我们将进一步探讨这种指针（以及指向空指针的各种影响）。

#### 空指针简介

除了内存地址外，指针还可以存储一个额外的值：空值。空值（通常简称为 null）是一个特殊值，表示某个值不存在。当指针存储空值时，意味着该指针不指向任何东西。这种指针称为空指针。

创建空指针最简单的方法是使用值初始化：
```cpp
int main()
{
    int* ptr {}; // ptr 现在是空指针，不持有任何地址

    return 0;
}
```

> [!SUCCESS] 最佳实践
> 如果你没有用有效对象的地址来初始化指针，请对指针进行值初始化（使其成为空指针）。

由于我们可以使用赋值来改变指针指向的内容，最初设置为空的指针后来可以被改变为指向一个有效对象：
```cpp
#include <iostream>

int main()
{
    int* ptr {}; // ptr 是空指针，不持有任何地址

    int x { 5 };
    ptr = &x; // ptr 现在指向对象 x（不再为空指针）

    std::cout << *ptr << '\n'; // 通过解引用 ptr 打印 x 的值

    return 0;
}
```

#### nullptr 关键字

与 `true` 和 `false` 关键字分别代表布尔字面量值类似，nullptr 关键字代表一个空指针字面量。我们可以使用 `nullptr` 来显式地初始化或为指针赋一个空值。
```cpp title=null
int main()
{
    int* ptr { nullptr }; // 可以用 nullptr 初始化为空指针

    int value { 5 };
    int* ptr2 { &value }; // ptr2 是有效指针
    ptr2 = nullptr; // 可以赋值 nullptr 使其变为空指针

    someFunction(nullptr); // 也可以向指针参数传入 nullptr

    return 0;
}
```

在上面的例子中，我们使用赋值操作将 `ptr2` 的值设置为 `nullptr` ，使 `ptr2` 成为一个空指针。

> [!SUCCESS] 最佳实践
> 当你需要为初始化、赋值或向函数传递空指针时，使用 `nullptr` 。

#### 解引用空指针会导致未定义行为

就像解引用悬空（或野）指针会导致未定义行为一样，解引用空指针也会导致未定义行为。在大多数情况下，这会导致你的应用程序崩溃。

以下程序说明了这一点，当你运行它时，它可能会异常崩溃或终止（尽管试一试，不会伤害你的机器）：
```cpp
#include <iostream>

int main()
{
    int* ptr {}; // 创建空指针
    std::cout << *ptr << '\n'; // 解引用空指针

    return 0;
}
```

从概念上讲，这是有道理的。解引用一个指针意味着“去指针指向的地址并访问那里的值”。一个空指针包含一个空值，从语义上讲，这意味着指针没有指向任何东西。那么它会访问什么值呢？

不小心解引用空指针和悬空指针是 C++ 程序员最常见的错误之一，也是 C++ 程序在实际中崩溃的最常见原因。

> [!DANGER] 警告
> 每次使用指针时，你都需要格外小心，确保你的代码没有解引用空指针或悬空指针，因为这将导致未定义行为（很可能是应用程序崩溃）。

#### 检查空指针

就像我们可以使用条件语句来测试布尔值是否为 `true` 或 `false` 一样，我们也可以使用条件语句来测试一个指针是否具有值 `nullptr` ：
```cpp
#include <iostream>

int main()
{
    int x { 5 };
    int* ptr { &x };

    if (ptr == nullptr) // 显式测试是否相等
        std::cout << "ptr is null\n";
    else
        std::cout << "ptr is non-null\n";

    int* nullPtr {};
    std::cout << "nullPtr is " << (nullPtr==nullptr ? "null\n" : "non-null\n"); // 显式测试是否相等

    return 0;
}
```

上述程序输出：
<pre>
ptr is non-null
nullPtr is null
</pre>

我们知道整数值会隐式转换为布尔值：整数值 `0` 转换为布尔值 `false` ，其他任何整数值转换为布尔值 `true` 。

类似地，指针也会隐式转换为布尔值：空指针转换为布尔值 `false` ，非空指针转换为布尔值 `true` 。这允许我们跳过显式测试 `nullptr` ，而直接使用隐式转换为布尔值来测试指针是否为空指针。以下程序与前面的程序等效：
```cpp
#include <iostream>

int main()
{
    int x { 5 };
    int* ptr { &x };

    // 指针在为空时转换为 false，非空时转换为 true
    if (ptr) // 隐式转换为布尔值
        std::cout << "ptr is non-null\n";
    else
        std::cout << "ptr is null\n";

    int* nullPtr {};
    std::cout << "nullPtr is " << (nullPtr ? "non-null\n" : "null\n"); // 隐式转换为布尔值

    return 0;
}
```

> [!DANGER] 警告
> 条件语句只能用来区分空指针和非空指针。没有方便的方法来确定一个非空指针是否指向一个有效的对象或悬空（指向一个无效的对象）。

#### 使用 nullptr 来避免悬空指针

上面我们提到，对一个为空或悬空的指针进行解引用会导致未定义行为。因此，我们需要确保我们的代码不会出现这两种情况。

我们可以通过使用条件语句来确保指针非空，然后再尝试解引用它，从而轻松避免对空指针进行解引用：
```cpp
// 假设 ptr 可能为空也可能非空
if (ptr) // 如果 ptr 非空
    std::cout << *ptr << '\n'; // 可以解引用
else
    // 处理不需要解引用 ptr 的其他逻辑（打印错误信息、什么都不做等）
```

但是悬空指针呢？由于没有办法检测指针是否悬空，我们需要从一开始就避免程序中出现任何悬空指针。我们通过确保任何不指向有效对象的指针都设置为 `nullptr` 来实现这一点。

那样的话，在解引用一个指针之前，我们只需要测试它是否为空——如果它非空，我们就假定这个指针不是悬空指针。

> [!SUCCESS] 最佳实践
> 指针应该要么持有有效对象的地址，要么设置为 nullptr。这样我们只需要测试指针是否为空，并且可以假设任何非空指针都是有效的。

不幸的是，避免悬空指针并不总是容易的：当对象被销毁时，指向该对象的任何指针都会变成悬空指针。这样的指针不会自动置为 `nullptr` ！确保所有刚被销毁的对象的指针都正确地设置为 `nullptr` 是程序员的职责。

> [!DANGER] 警告
> 当对象被销毁时，指向该对象的任何指针将悬空（它们不会自动设置为 `nullptr` ）。检测这些情况并确保这些指针随后设置为 `nullptr` 是你的责任。

#### 传统的空指针字面量：0 和 NULL ==OPTIONAL==

第一个是字面量 `0` 。在指针的上下文中，字面量 `0` 被特别定义为表示空值，并且是唯一可以将整数字面量赋值给指针的情况。
```cpp
int main()
{
    float* ptr { 0 };  // ptr 现在是空指针（仅示例，不要这样写）

    float* ptr2; // ptr2 未初始化
    ptr2 = 0; // ptr2 现在是空指针（仅示例，不要这样写）

    return 0;
}
```

> [!CITE] 顺便一提
> 在现代架构中，地址 `0` 通常用于表示空指针。然而，C++标准并未保证此值，有些架构使用其他值。在空指针的上下文中使用的字面量 `0` 将被转换为该架构用于表示空指针的地址。

此外，还有一个名为 `NULL` 的预处理宏（定义在头文件中）。该宏继承自 C 语言，在 C 语言中通常用于表示空指针。
```cpp
#include <cstddef> // 用于 NULL

int main()
{
    double* ptr { NULL }; // ptr 是空指针

    double* ptr2; // ptr2 未初始化
    ptr2 = NULL; // ptr2 现在是空指针

    return 0;
}
```

**在现代 C++中应避免使用 `0` 和 `NULL` （应使用 `nullptr` ）。**

#### 尽可能使用引用而不是指针

指针和引用都能让我们间接访问其他对象。

指针具有额外的能力，即能够改变它们指向的内容，以及能够指向空值。然而，这些指针的能力也具有内在的危险性：空指针存在被解引用的风险，而改变指针指向的内容的能力更容易创建悬空指针：
```cpp
int main()
{
    int* ptr { };

    {
        int x{ 5 };
        ptr = &x; // 指向即将被销毁的对象（引用无法这么做）
    } // ptr 变为悬空指针，指向无效对象

    if (ptr) // 条件为真，因为 ptr 不是 nullptr
        std::cout << *ptr; // 未定义行为

    return 0;
}
```

由于引用不能绑定到空值，我们不必担心空引用。而且因为引用在创建时必须绑定到一个有效的对象，然后就不能再重新绑定，悬空引用更难创建。

由于引用更安全，应优先使用引用而非指针，除非需要指针提供的额外功能。

> [!SUCCESS] 最佳实践
> 除非需要指针提供的额外功能，否则优先使用引用。

### 指针与常量

考虑以下代码片段：
```cpp
int main()
{
    int x { 5 };
    int* ptr { &x }; // ptr 是普通（非常量）指针

    int y { 6 };
    ptr = &y; // 可以改为指向其他值

    *ptr = 7; // 可以修改所指地址处的值

    return 0;
}
```

对于普通（非常量）指针，我们可以改变指针指向的内容（通过给指针分配一个新的地址来存储）或改变存储地址处的值（通过给解引用的指针赋新值）。

然而，如果我们想要指向的值是常量呢？
```cpp
int main()
{
    const int x { 5 }; // x 现在是常量
    int* ptr { &x };   // 编译错误：不能从 const int* 转为 int*

    return 0;
}
```

上面的代码无法编译——我们不能让普通指针指向一个常量变量。这很合理：常量变量的值不能改变。如果允许程序员将非常量指针指向常量值，那么程序员就可以解引用指针并改变值。这会违反常量属性。

#### 指向常量值的指针

指向常量值的指针（有时简称为 `pointer to const` ）是一个（非常量）指针，它指向一个常量值。

要声明一个指向常量值的指针，在指针的数据类型前使用 `const` 关键字：
```cpp
int main()
{
    const int x{ 5 };
    const int* ptr { &x }; // 正确：ptr 指向 "const int"

    *ptr = 6; // 错误：不能修改常量值

    return 0;
}
```

在上面的示例中， `ptr` 指向一个 `const int` 。由于所指向的数据类型是常量，因此所指向的值不能被改变。

然而，由于指向常量的指针本身不是常量（它只是指向一个常量值），我们可以通过给指针分配新的地址来改变它指向的内容：
```cpp
int main()
{
    const int x{ 5 };
    const int* ptr { &x }; // ptr 指向 const int x

    const int y{ 6 };
    ptr = &y; // 正确：ptr 现在指向 const int y

    return 0;
}
```

就像指向常量的引用一样，指向常量的指针也可以指向非常量变量。指向常量的指针将所指向的值视为常量，无论该地址处的对象最初是否定义为常量：
```cpp
int main()
{
    int x{ 5 }; // 非常量
    const int* ptr { &x }; // ptr 指向 "const int"

    *ptr = 6;  // 错误：ptr 指向 "const int"，不能通过 ptr 修改值
    x = 6; // 正确：通过非常量标识符 x 访问时仍为非常量

    return 0;
}
```

#### 常量指针

我们还可以使指针本身成为常量。<font color="#4dfe50">常量指针</font>(const pointer)是指针地址在初始化后不能改变的指针。

要声明一个常量指针，在指针声明中的星号后使用 `const` 关键字：
```cpp
int main()
{
    int x{ 5 };
    int* const ptr { &x }; // 星号后面的 const 表示这是常量指针

    return 0;
}
```

在上述情况下， `ptr` 是一个指向（非常量）int 值的常量指针。

和普通的常量变量一样，常量指针必须在定义时初始化，并且这个值不能通过赋值来改变：
```cpp
int main()
{
    int x{ 5 };
    int y{ 6 };

    int* const ptr { &x }; // 正确：常量指针初始化为 x 的地址
    ptr = &y; // 错误：常量指针初始化后不能改变

    return 0;
}
```

然而，因为所指向的值不是常量，可以通过解引用常量指针来改变所指向的值：
```cpp
int main()
{
    int x{ 5 };
    int* const ptr { &x }; // ptr 将一直指向 x

    *ptr = 6; // 正确：被指向的值是非常量

    return 0;
}
```

#### 指向常量的常量指针

最后，可以通过在类型之前和星号之后都使用 `const` 关键字来声明指向常量值的常量指针：
```cpp
int main()
{
    int value { 5 };
    const int* const ptr { &value }; // 指向常量值的常量指针

    return 0;
}
```

一个指向常量值的常量指针不能改变其地址，也不能通过该指针改变它所指向的值。它只能通过解引用来获取它所指向的值。

#### 指针与常量回顾

总而言之，你只需要记住 4 条规则，而且它们非常合理：
- 一个非常量指针（例如 `int* ptr` ）可以被分配另一个地址，以改变它所指向的内容。
- 一个常量指针（例如 `int* const ptr` ）始终指向同一个地址，并且这个地址不能被改变。
- 一个指向非常量值的指针（例如 `int* ptr` ）可以改变它所指向的值。这些指针不能指向常量值。
- 指向常量值的指针（例如 `const int* ptr` ）在通过指针访问时将值视为常量，因此不能改变它所指向的值。这些可以指向常量或非常量的左值（但不能指向右值，因为右值没有地址）。

保持声明语法清晰可能有点挑战：
- 星号（\*）之前的 `const` （例如 `const int* ptr` ）与被指向的类型相关联。因此，这是一个指向常量值的指针，通过该指针不能修改值。
- 星号（\*）之后的 `const` （例如 `int* const ptr` ）与指针本身相关联。因此，该指针不能被分配新的地址。

```cpp
int main()
{
    int v{ 5 };

    int* ptr0 { &v };             // 指向 "int"，自身非常量：可修改值或地址
    const int* ptr1 { &v };       // 指向 "const int"，自身非常量：只能修改地址
    int* const ptr2 { &v };       // 指向 "int"，自身为常量：只能修改值
    const int* const ptr3 { &v }; // 指向 "const int"，自身为常量：不能修改值或地址

    // const 在 * 左侧时，修饰的是值
    // const 在 * 右侧时，修饰的是指针本身

    return 0;
}
```

### 值传递与引用传递

这里有一个示例程序，展示了对象 `std::string` 使用值传递和引用传递：
```cpp
#include <iostream>
#include <string>

void printByValue(std::string val) // 形参是 str 的副本
{
    std::cout << val << '\n'; // 通过副本打印值
}

void printByReference(const std::string& ref) // 形参是绑定到 str 的引用
{
    std::cout << ref << '\n'; // 通过引用打印值
}

int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // 按值传递，会复制 str
    printByReference(str); // 按引用传递，不复制 str

    return 0;
}
```

当我们使用值传递时，函数参数 `val` 会接收参数的一个副本。因为参数是实参的一个副本，所以对 `val` 的任何修改都是对副本进行的，而不是对原始实参进行的。

当我们使用引用传递时，引用参数 `ref` 与实际参数绑定。这避免了复制参数。因为我们的引用参数是常量引用，所以我们不允许修改 `ref` 。但如果 `ref` 是非常量引用，我们对 `ref` 的任何修改都会改变 `str` 。

在两种情况下，调用者都提供了实际的对象（ `str` ）作为函数调用的参数。

### 地址传递

C++ 提供了第三种向函数传递值的方法，称为<font color="#4dfe50">地址传递</font>(**pass by address**)。在地址传递中，调用者不是提供一个对象作为参数，而是提供一个对象的地址（通过指针）。该指针（持有对象地址）被复制到被调用函数的指针参数中（该参数现在也持有对象的地址）。然后，该函数可以通过解引用该指针来访问传递的地址所对应的对象。

这是上述程序的一个添加了地址传递变体的版本：
```cpp
#include <iostream>
#include <string>

void printByValue(std::string val) // 形参是 str 的副本
{
    std::cout << val << '\n'; // 通过副本打印值
}

void printByReference(const std::string& ref) // 形参是绑定到 str 的引用
{
    std::cout << ref << '\n'; // 通过引用打印值
}

void printByAddress(const std::string* ptr) // 形参是保存 str 地址的指针
{
    std::cout << *ptr << '\n'; // 通过解引用指针打印值
}

int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // 按值传递，复制 str
    printByReference(str); // 按引用传递，不复制 str
    printByAddress(&str); // 按地址传递，不复制 str

    return 0;
}
```

注意这三个版本多么相似。让我们更详细地探讨地址传递的版本。

首先，因为我们希望我们的 `printByAddress()` 函数使用地址传递，我们将函数参数设为一个名为 `ptr` 的指针。由于 `printByAddress()` 将以只读方式使用 `ptr` ， `ptr` 是一个指向常量的指针。

```cpp
void printByAddress(const std::string* ptr)
{
    std::cout << *ptr << '\n'; // 通过解引用指针打印值
}
```

在 `printByAddress()` 函数内部，我们解引用 `ptr` 参数来访问所指向对象的值。

其次，当函数被调用时，我们不能直接传入 `str` 对象——我们需要传入 `str` 的地址。最简单的方法是使用取地址运算符(&)来获取一个指向 `str` 地址的指针：
```cpp
printByAddress(&str); // 使用取地址运算符获取 str 的地址
```

当执行此调用时， `&str` 将创建一个指针，该指针持有 `str` 的地址。然后，此地址被复制到函数参数 `ptr` 中，作为函数调用的一部分。由于 `ptr` 现在持有 `str` 的地址，当函数解引用 `ptr` 时，它将获取 `str` 的值，并将该值打印到控制台。

就这样。

尽管我们在上面的示例中使用了取地址运算符来获取 `str` 的地址，但如果我们已经有一个指针变量持有 `str` 的地址，我们也可以使用那个地址：
```cpp
int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // 按值传递，复制 str
    printByReference(str); // 按引用传递，不复制 str
    printByAddress(&str); // 按地址传递，不复制 str

    std::string* ptr { &str }; // 定义保存 str 地址的指针变量
    printByAddress(ptr); // 按地址传递，不复制 str

    return 0;
}
```

#### 地址传递不会复制指向的对象

考虑以下语句：
```cpp
std::string str{ "Hello, world!" };
printByAddress(&str); // 使用取地址运算符获取 str 的地址
```

正如我们在上文中提到的，复制一个对象是昂贵的，因此我们想要避免这种情况。当我们使用地址传递时，我们并不是复制实际的对象——我们只是将持有对象地址的指针从调用者复制到被调用函数。由于地址通常是 4 或 8 个字节，指针也是 4 或 8 个字节，因此复制指针总是很快的。

因此，就像引用传递一样，地址传递也是快速的，并且避免了复制实参对象。

#### 地址传递允许函数修改实参的值

当我们使用地址传递时，函数接收传递对象的地址，并通过解引用来访问它。由于这是实际传递的参数对象的地址（而不是对象的副本），如果函数参数是指向非常量的指针，函数可以通过指针参数来修改参数：
```cpp
#include <iostream>

void changeValue(int* ptr) // 注意：本例中 ptr 指向非常量
{
    *ptr = 6; // 将值改为 6
}

int main()
{
    int x{ 5 };

    std::cout << "x = " << x << '\n';

    changeValue(&x); // 将 x 的地址传给函数

    std::cout << "x = " << x << '\n';

    return 0;
}
```

这将会输出：
<pre>
x = 5
x = 6
</pre>

如您所见，参数被修改了，而且这种修改在 `changeValue()` 运行结束后仍然存在。

如果一个函数不应该修改传入的对象，函数参数应该声明为指向常量的指针：
```cpp
void changeValue(const int* ptr) // 注意：ptr 现在指向 const
{
    *ptr = 6; // 错误：不能修改常量值
}
```

出于与通常不使用普通（非指针、非引用）函数参数的许多相同原因，我们通常也不使用指向指针的函数参数。让我们提出两个断言：
- 一个 `const` 关键字用于将函数参数的指针声明为常量指针，几乎没什么价值（因为它对调用者没有影响，而且主要只是作为文档说明该指针不会改变）。
- 一个 `const` 关键字用于区分指向常量的指针和可以修改传入对象的非常量指针，其意义非常重要（因为调用者需要知道函数是否可能改变参数的值）。

如果我们只使用非常量指针作为函数参数，那么所有 `const` 的使用都是重要的。一旦我们开始使用 `const` 作为常量指针的函数参数，就变得更加难以判断某个 `const` 的使用是否重要。更重要的是，这也使得我们更难注意到非常量指针参数。例如：
```cpp
void foo(const char* source, char* dest, int count);             // 使用非常量指针时，所有 const 都重要
void foo(const char* const source, char* const dest, int count); // 使用常量指针时，指向非常量的 dest 可能不易察觉
```

在前一种情况下，很容易看出 `source` 是一个指向常量的指针，而 `dest` 是一个指向非常量的指针。在后一种情况下，要看出 `dest` 是一个指向非常量的常量指针，其指向的对象可以被函数修改，要困难得多！

> [!SUCCESS] 最佳实践
> 优先使用指向常量的函数参数，而不是指向非常量的函数参数，除非函数需要修改传入的对象。
> 
> 除非有特定的理由，否则不要将函数参数设为指向常量的指针。

#### 空值检查

现在考虑这个看起来相当无害的程序：
```cpp
#include <iostream>

void print(int* ptr)
{
	std::cout << *ptr << '\n';
}

int main()
{
	int x{ 5 };
	print(&x);

	int* myPtr {};
	print(myPtr);

	return 0;
}
```

当运行这个程序时，它会打印出值 `5` ，然后很可能崩溃。

在调用 `print(myPtr)` 时， `myPtr` 是一个空指针，因此函数参数 `ptr` 也将是一个空指针。当在函数体中解引用这个空指针时，将导致未定义行为。

在地址传递中，应确保在解引用值之前指针不是空指针。一种方法是通过使用条件语句来实现这一点：
```cpp
#include <iostream>

void print(int* ptr)
{
    if (ptr) // 如果 ptr 不是空指针
    {
        std::cout << *ptr << '\n';
    }
}

int main()
{
	int x{ 5 };

	print(&x);
	print(nullptr);

	return 0;
}
```

在上述程序中，我们测试 `ptr` 以确保在解引用它之前它不是空。虽然这对于这样一个简单的函数来说是可行的，但在更复杂的函数中，这可能导致冗余逻辑（多次测试 ptr 是否为空）或函数主要逻辑的嵌套（如果包含在代码块中）。

在大多数情况下，采取相反的做法更有效：将函数参数是否为空作为先决条件进行测试，并立即处理负面的情况：
```cpp
#include <iostream>

void print(int* ptr)
{
    if (!ptr) // 如果 ptr 是空指针，则提前返回
        return;

    // 走到这里说明 ptr 有效
    // 因此不需要更多判断或嵌套

    std::cout << *ptr << '\n';
}

int main()
{
	int x{ 5 };

	print(&x);
	print(nullptr);

	return 0;
}
```

如果函数参数永远不应该为空，可以使用 `assert`（因为断言的目的是记录那些本不应发生的情况）：
```cpp
#include <iostream>
#include <cassert>

void print(const int* ptr) // 现在是指向 const int 的指针
{
    assert(ptr); // 若传入空指针，在调试模式下终止程序（本不应发生）

    // （可选）在生产模式中作为错误处理，避免发生时崩溃
	if (!ptr)
		return;

	std::cout << *ptr << '\n';
}

int main()
{
	int x{ 5 };

	print(&x);
	print(nullptr);

	return 0;
}
```

#### 优先使用 (const) 引用传递

请注意，上述示例中的函数 `print()` 处理空值的效果不佳——它实际上只是终止了函数。考虑到这一点，为什么还要允许用户传递空值呢？引用传递与地址传递具有相同的好处，但避免了意外解引用空指针的风险。

引用传递相比地址传递还有一些其他优势。

首先，因为地址传递要求对象必须有地址，所以只有左值可以传递地址（因为右值没有地址）。常量引用传递更加灵活，因为它可以接受左值和右值：
```cpp
#include <iostream>

void printByValue(int val) // 形参是实参的副本
{
    std::cout << val << '\n'; // 通过副本打印值
}

void printByReference(const int& ref) // 形参是绑定到实参的引用
{
    std::cout << ref << '\n'; // 通过引用打印值
}

void printByAddress(const int* ptr) // 形参是保存实参地址的指针
{
    std::cout << *ptr << '\n'; // 通过解引用指针打印值
}

int main()
{
    printByValue(5);     // 正确（但会复制）
    printByReference(5); // 正确（因为形参是常量引用）
    printByAddress(&5);  // 错误：不能对右值取地址

    return 0;
}
```

其次，引用传递的语法很自然，因为我们可以直接传递字面量或对象。而使用地址传递，我们的代码中会充斥着与号（&）和星号（\*）。

在现代 C++中，大多数可以通过地址传递完成的事情，通过其他方法完成会更好。遵循这个通用原则：“尽可能使用引用传递，必要时使用地址传递”。

> [!SUCCESS] 最佳实践
> 除非有特定理由使用地址传递，否则优先选择引用传递。

#### 地址传递用于“可选(optional)”参数

地址传递的一个更常见的用途是允许函数接受一个“可选”参数。这比描述更容易通过示例来说明：
```cpp
#include <iostream>

void printIDNumber(const int *id=nullptr)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // 还不知道用户的 ID

    int userid { 34 };
    printIDNumber(&userid); // 现在知道用户的 ID

    return 0;
}
```

这个示例输出：
<pre>
Your ID number is not known.
Your ID number is 34.
</pre>

在这个程序中， `printIDNumber()` 函数有一个通过地址传递的参数，并且默认值为 `nullptr` 。在 `main()` 中，我们调用了这个函数两次。第一次调用时，我们不知道用户的 ID，所以没有参数调用 `printIDNumber()` 。 `id` 参数默认为 `nullptr` ，函数打印 `Your ID number is not known.` 。对于第二次调用，我们现在有一个有效的 id，所以调用 `printIDNumber(&userid)` 。 `id` 参数接收 `userid` 的地址，所以函数打印 `Your ID number is 34.` 。

然而，在许多情况下，函数重载是实现相同结果的更好选择：
```cpp
#include <iostream>

void printIDNumber()
{
    std::cout << "Your ID is not known\n";
}

void printIDNumber(int id)
{
    std::cout << "Your ID is " << id << "\n";
}

int main()
{
    printIDNumber(); // 还不知道用户的 ID

    int userid { 34 };
    printIDNumber(userid); // 现在知道用户是 34

    printIDNumber(62); // 也可以传入右值

    return 0;
}
```

这有几个优点：我们不再需要担心空指针引用，并且可以将字面量或其他右值作为参数传递。

#### 改变指针参数指向的内容

当我们把一个地址传递给函数时，这个地址会从实参复制到指针参数中（这很好，因为复制地址很快）。现在考虑以下程序：
```cpp
#include <iostream>

// [[maybe_unused]] 用于消除 ptr2 被赋值但未使用的警告
void nullify([[maybe_unused]] int* ptr2)
{
    ptr2 = nullptr; // 将函数参数置为空指针
}

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // ptr 指向 x

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");

    nullify(ptr);

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");
    return 0;
}
```

该程序输出：
<pre>
ptr is non-null
ptr is non-null
</pre>

如您所见，改变指针参数所持有的地址对实参所持有的地址没有影响（ `ptr` 仍然指向 `x` ）。当函数 `nullify()` 被调用时， `ptr2` 接收到传入地址的副本（在这种情况下，是 `ptr` 所持有的地址，即 `x` 的地址）。当函数改变 `ptr2` 所指向的内容时，这只会影响 `ptr2` 所持有的副本。

那么，如果我们想允许一个函数改变一个指针参数指向的内容，又该怎么办呢？

#### 通过地址...通过引用？

是的，这是可行的。就像我们可以通过引用传递普通变量一样，我们也可以通过引用传递指针。这是上面程序中 `ptr2` 改为地址引用的相同代码：
```cpp
#include <iostream>

void nullify(int*& refptr) // refptr 现在是指向指针的引用
{
    refptr = nullptr; // 将函数参数置为空指针
}

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // ptr 指向 x

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");

    nullify(ptr);

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");
    return 0;
}
```

该程序输出：
<pre>
ptr is non-null
ptr is null
</pre>

因为 `refptr` 现在是一个指向指针的引用，当 `ptr` 作为参数传递时， `refptr` 绑定到 `ptr` 。这意味着对 `refptr` 的任何更改都会反映在 `ptr` 上。

> [!NOTE] 旁注
> 由于指向指针的引用并不常见，很容易混淆语法（是 `int*&` 还是 `int&*` ？）。好消息是，如果你弄反了，编译器会报错，因为不能有指向引用的指针（因为指针必须持有对象的地址，而引用不是对象）。然后你就可以调换过来。

#### 为什么不再推荐使用 `0` 或 `NULL` （可选）

在这一小节中，我们将解释为什么不再推荐使用 `0` 或 `NULL` 。

字面量 `0` 可以被解释为整数字面量，或者为空指针字面量。在某些情况下，我们意图不明确——在某些这些情况下，编译器可能假设我们指的是其中一个，而我们实际指的是另一个——这会导致程序行为出现意想不到的后果。

预处理器宏 `NULL` 的定义不由语言标准定义。它可以被定义为 `0` ， `0L` ， `((void*)0)` ，或者完全是其他东西。

编译器可以通过函数调用中传递的参数来确定您想要使用哪个重载函数。

在使用 `0` 或 `NULL` 时，这可能会导致问题：
```cpp
#include <iostream>
#include <cstddef> // 用于 NULL

void print(int x) // 该函数接受一个整数
{
	std::cout << "print(int): " << x << '\n';
}

void print(int* ptr) // 该函数接受一个整型指针
{
	std::cout << "print(int*): " << (ptr ? "non-null\n" : "null\n");
}

int main()
{
	int x{ 5 };
	int* ptr{ &x };

    print(ptr);  // 总是调用 print(int*)，因为 ptr 的类型是 int*
    print(0);    // 总是调用 print(int)，因为 0 是整数字面量

    print(NULL); // 这一行可能出现以下情况：
    // 调用 print(int)（Visual Studio 会这样做）
    // 调用 print(int*)
    // 产生二义性编译错误（gcc 与 Clang 会这样做）

    print(nullptr); // 总是调用 print(int*)

	return 0;
}
```

在作者使用的机器上（使用 Visual Studio），它会打印：
<pre>
print(int*): non-null
print(int): 0
print(int): 0
print(int*): null
</pre>

当将整数值 `0` 作为参数传递时，编译器会优先选择 `print(int)` 而不是 `print(int*)` 。当我们将 `print(int*)` 与空指针参数一起调用时，这可能会导致意想不到的结果。

当 `NULL` 被定义为值 `0` 时， `print(NULL)` 也会调用 `print(int)` ，而不是像你可能期望的那样调用 `print(int*)` （空指针字面量）。当 `NULL` 没有被定义为 `0` 时，可能会出现其他行为，比如调用 `print(int*)` 或编译错误。

使用 `nullptr` 可以消除这种歧义（它将始终调用 `print(int*)` ），因为 `nullptr` 只会匹配指针类型。

#### std:: nullptr_t (可选)

由于 `nullptr` 可以与函数重载中的整数值区分开来，它必须具有不同的类型。那么 `nullptr` 的类型是什么？答案是 `nullptr` 的类型是 `std::nullptr_t` （在头文件中定义）。 `std::nullptr_t` 只能存储一个值： `nullptr` ！虽然这看起来有点傻，但在一种情况下很有用。如果我们想编写一个只接受 `nullptr` 字面量参数的函数，我们可以将参数设置为 `std::nullptr_t` 。

```cpp
#include <iostream>
#include <cstddef> // 用于 std::nullptr_t

void print(std::nullptr_t)
{
    std::cout << "in print(std::nullptr_t)\n";
}

void print(int*)
{
    std::cout << "in print(int*)\n";
}

int main()
{
    print(nullptr); // 调用 print(std::nullptr_t)

    int x { 5 };
    int* ptr { &x };

    print(ptr); // 调用 print(int*)

    ptr = nullptr;
    print(ptr); // 调用 print(int*)（因为 ptr 的类型是 int*）

    return 0;
}
```

在上面的例子中，函数调用 `print(nullptr)` 解析为函数 `print(std::nullptr_t)` 在 `print(int*)` 上，因为它不需要转换。

可能有点令人困惑的情况是我们当 `ptr` 持有值 `nullptr` 时调用 `print(ptr)` 。记住函数重载是基于类型而不是值的匹配，而 `ptr` 的类型是 `int*` 。因此， `print(int*)` 将被匹配。在这个情况下， `print(std::nullptr_t)` 甚至不会被考虑，因为指针类型不会隐式转换为 `std::nullptr_t` 。

你可能永远不会需要使用这个，但知道它总没有坏处。

#### 只有值传递

现在你已经了解了引用、地址和值传递的基本区别，让我们暂时采取一种简化的观点。 :)

虽然编译器通常可以完全优化掉引用，但在某些情况下这是不可能的，并且确实需要一个引用。引用通常由编译器使用指针实现。这意味着在底层，按引用传递本质上就是按地址传递。

在上一课中，我们提到按地址传递只是将调用者的地址复制给被调用函数——这实际上就是按值传递地址。

因此，我们可以得出结论：C++ 真的是按值传递一切！按地址（和引用）传递的特性完全来自于我们可以通过传递的地址进行解引用来改变参数，而这是无法用普通值参数做到的！

### 通过引用返回和通过地址返回

在之前的课程中，我们讨论了当通过值传递参数时，参数的副本会被传递到函数参数中。对于基本类型（复制成本较低），这是没问题的。但对于类类型（如 `std::string` ），复制通常成本很高。我们可以通过使用（常量）引用传递（或按地址传递）来避免进行昂贵的复制。

在按值返回时，我们也会遇到类似的情况：返回值的副本会被传递回调用者。如果函数的返回类型是类类型，这可能很昂贵。
```cpp
std::string returnByValue(); // 返回 std::string 的副本（成本高）
```

#### 通过引用返回

当我们需要将类类型返回给调用者时，我们可能（也可能不）希望通过引用来返回。通过引用返回会返回一个绑定到被返回对象的引用，从而避免复制返回值。要通过引用返回，我们只需将函数的返回值定义为引用类型：
```cpp
std::string&       returnByReference(); // 返回指向现有 std::string 的引用（成本低）
const std::string& returnByReferenceToConst(); // 返回指向现有 std::string 的常量引用（成本低）
```

这里有一个学术程序来演示通过引用返回的机制：
```cpp
#include <iostream>
#include <string>

const std::string& getProgramName() // 返回常量引用
{
    static const std::string s_programName { "Calculator" }; // 具有静态存储期，程序结束时销毁

    return s_programName;
}

int main()
{
    std::cout << "This program is named " << getProgramName();

    return 0;
}
```

该程序输出：
<pre>
This program is named Calculator
</pre>

因为 `getProgramName()` 返回一个常量引用，当执行 `return s_programName` 这行代码时， `getProgramName()` 将返回一个指向 `s_programName` 的常量引用（从而避免复制）。这个常量引用可以被调用者用来访问 `s_programName` 的值，该值将被打印。

#### 被引用返回的对象必须在函数返回后仍然存在

使用引用返回有一个主要的注意事项：程序员必须确保被引用的对象的生命周期长于返回引用的函数。否则，返回的引用将悬空（引用一个已经被销毁的对象），使用该引用将导致未定义行为。

在上面的程序中，因为 `s_programName` 具有静态持续时间， `s_programName` 将一直存在到程序的结束。当 `main()` 访问返回的引用时，它实际上是在访问 `s_programName` ，这是没问题的，因为 `s_programName` 直到稍后才会被销毁。

现在让我们修改上面的程序，以展示当我们的函数返回一个悬空引用时会发生什么
```cpp
#include <iostream>
#include <string>

const std::string& getProgramName()
{
    const std::string programName { "Calculator" }; // 非静态局部变量，函数结束时销毁

    return programName;
}

int main()
{
    std::cout << "This program is named " << getProgramName(); // 未定义行为

    return 0;
}
```

这个程序的结果是未定义的。当 `getProgramName()` 返回时，一个绑定到局部变量 `programName` 的引用被返回。然后，因为 `programName` 是一个具有自动持续时间的局部变量， `programName` 在函数结束时被销毁。这意味着返回的引用现在是悬空的，在 `main()` 函数中使用 `programName` 会导致未定义行为。

现代编译器如果你尝试通过引用返回局部变量（因此上述程序可能甚至无法编译），将会产生警告或错误，但编译器有时难以检测更复杂的情况。

> [!DANGER] 警告
> 通过引用返回的对象必须存在于返回引用的函数作用域之外，否则会产生悬空引用。永远不要通过引用返回（非静态）局部变量或临时变量。

#### 生命周期扩展不能跨函数边界工作

让我们来看一个通过引用返回临时对象的例子：
```cpp
#include <iostream>

const int& returnByConstReference()
{
    return 5; // 返回指向临时对象的常量引用
}

int main()
{
    const int& ref { returnByConstReference() };

    std::cout << ref; // 未定义行为

    return 0;
}
```

在上面的程序中， `returnByConstReference()` 返回一个整型字面量，但函数的返回类型是 `const int&` 。这导致创建并返回一个绑定到持有值 5 的临时对象的临时引用。这个返回的引用被复制到调用者的作用域中的临时引用中。临时对象随后超出作用域，留下调用者作用域中的临时引用悬空。

当调用者作用域中的临时引用绑定到常量引用变量 `ref` (在 `main()` ) 时，已经太迟无法延长临时对象的生命周期——因为它已经被销毁了。因此 `ref` 是一个悬空引用，使用 `ref` 的值将导致未定义行为。

这里有一个不太明显的例子，它同样不能工作：
```cpp
#include <iostream>

const int& returnByConstReference(const int& ref)
{
    return ref;
}

int main()
{
    // 情况 1：直接绑定
    const int& ref1 { 5 }; // 延长生命周期
    std::cout << ref1 << '\n'; // 正确

    // 情况 2：间接绑定
    const int& ref2 { returnByConstReference(5) }; // 绑定到悬空引用
    std::cout << ref2 << '\n'; // 未定义行为

    return 0;
}
```

在案例 2 中，会创建一个临时对象来持有值 `5` ，该对象被函数参数 `ref` 绑定。函数仅将这个引用返回给调用者，调用者随后使用该引用来初始化 `ref2` 。由于这不是直接绑定到临时对象（因为引用通过函数进行了传递），所以不会应用生命周期扩展。这导致 `ref2` 悬空，其后续使用是未定义行为。

> [!DANGER] 警告
> 引用生命周期的扩展不能跨越函数边界。

#### 不要通过引用返回非常量静态局部变量

在上述原始示例中，我们通过引用返回了一个常量静态局部变量，以简单的方式说明了通过引用返回的机制。然而，通过引用返回非常量静态局部变量是比较非惯用的，通常应避免。这里有一个简化的示例，说明了可能发生的一种此类问题：
```cpp
#include <iostream>
#include <string>

const int& getNextId()
{
    static int s_x{ 0 }; // 注意：变量是非常量
    ++s_x; // 生成下一个 id
    return s_x; // 返回对它的引用
}

int main()
{
    const int& id1 { getNextId() }; // id1 是引用
    const int& id2 { getNextId() }; // id2 是引用

    std::cout << id1 << id2 << '\n';

    return 0;
}
```

该程序输出：
<pre>
22
</pre>

这是因为 `id1` 和 `id2` 引用的是同一个对象（静态变量 `s_x` ），所以当任何东西（例如 `getNextId()` ）修改这个值时，所有引用现在都在访问修改后的值。

上述示例可以通过将 `id1` 和 `id2` 设为普通变量（而不是引用），这样它们会保存返回值的副本，而不是 `s_x` 的引用来修复。

另一个常见问题是，对于返回非常量静态局部引用的程序，没有标准的方法来将 `s_x` 重置回默认状态。这类程序要么必须使用非常规的解决方案（例如，重置函数参数），要么只能通过退出并重新启动程序来重置。

---
##### 对于高级读者==optional==

这里再举一个不太明显的同一问题的例子：
```cpp
#include <iostream>
#include <string>
#include <string_view>

std::string& getName()
{
    static std::string s_name{};
    std::cout << "请输入姓名: ";
    std::cin >> s_name;
    return s_name;
}

void printFirstAlphabetical(const std::string& s1, const std::string& s2)
{
    if (s1 < s2)
        std::cout << s1 << " 在字母顺序上早于 " << s2 << '\n';
    else
        std::cout << s2 << " 在字母顺序上早于 " << s1 << '\n';
}

int main()
{
    printFirstAlphabetical(getName(), getName());

    return 0;
}
```

这是该程序的一次运行结果：
<pre>
请输入姓名: Dave
请输入姓名: Stan
Stan 在字母顺序上早于 Stan
</pre>

在这个例子中， `getName()` 返回静态局部 `s_name` 的引用。用 `s_name` 的引用初始化 `const std::string&` 会导致 `std::string&` 绑定到 `s_name` （而不是复制它）。

因此， `s1` 和 `s2` 最终都看到了 `s_name` （它被赋值为我们最后输入的姓氏）。

请注意，如果我们使用 `std::string_view` 参数，当底层的 `std::string` 改变时，第一个 `std::string_view` 参数将被失效。

---

另一个常见问题是，对于返回非常量静态局部引用的程序，没有标准的方法来将 `s_x` 重置回默认状态。这类程序要么必须使用非常规的解决方案（例如，重置函数参数），要么只能通过退出并重新启动程序来重置。

> [!SUCCESS] 最佳实践
> 避免返回对非常量局部静态变量的引用。

将一个常量引用返回给一个常量局部静态变量有时会这样做，如果通过引用返回的局部变量创建和/或初始化成本很高（这样我们就不必每次函数调用时都重新创建变量）。但这很少见。

#### 用返回的引用为普通变量赋值/初始化会创建一个副本

如果一个函数返回一个引用，并且该引用被用来初始化或赋值给一个非引用变量，那么返回值将被复制（就像它被按值返回一样）。
```cpp
#include <iostream>
#include <string>

const int& getNextId()
{
    static int s_x{ 0 };
    ++s_x;
    return s_x;
}

int main()
{
    const int id1 { getNextId() }; // id1 是普通变量，接收引用返回值的副本
    const int id2 { getNextId() }; // id2 是普通变量，接收引用返回值的副本

    std::cout << id1 << id2 << '\n';

    return 0;
}
```

在上述示例中， `getNextId()` 返回的是一个引用，而 `id1` 和 `id2` 是非引用变量。在这种情况下，返回的引用的值会被复制到普通变量中。因此，这个程序会打印：
<pre>
12
</pre>

另外请注意，如果程序返回一个悬空引用，在复制之前引用会保持悬空，这会导致未定义行为：
```cpp
#include <iostream>
#include <string>

const std::string& getProgramName() // 返回常量引用
{
    const std::string programName{ "Calculator" };

    return programName;
}

int main()
{
    std::string name { getProgramName() }; // 复制悬空引用的值
    std::cout << "This program is named " << name << '\n'; // 未定义行为

    return 0;
}
```

#### 通过引用返回引用参数是可以的

有很多情况下通过引用返回对象是合理的，我们将在未来遇到很多这样的例子。然而，现在我们可以展示一个有用的例子。

如果参数通过引用传递给函数，那么通过引用返回该参数是安全的。这是有道理的：为了将一个实参传递给函数，该实参必须在调用者的作用域中存在。当被调用的函数返回时，该对象仍然必须在调用者的作用域中存在。

这里是一个这样的函数的简单示例：
```cpp
#include <iostream>
#include <string>

// 接收两个 std::string，返回字母顺序更靠前的那个
const std::string& firstAlphabetical(const std::string& a, const std::string& b)
{
    return (a < b) ? a : b; // 使用 std::string 的 operator< 判断字母顺序
}

int main()
{
	std::string hello { "Hello" };
	std::string world { "World" };

	std::cout << firstAlphabetical(hello, world) << '\n';

	return 0;
}
```

这段代码输出：
<pre>
Hello
</pre>

在上述函数中，调用者通过常量引用传递了两个 std:: string 对象，而字母顺序上先出现的字符串会通过常量引用返回。如果我们使用按值传递和按值返回，我们将最多创建三个 std:: string 的副本（每个参数一个，返回值一个）。通过使用按引用传递/按引用返回，我们可以避免这些副本。

#### 允许将以常量引用传递的右值，继续以常量引用返回

当常量引用参数的实参是一个右值时，仍然可以以常量引用的方式返回该参数。

这是因为右值在它们被创建的完整表达式的末尾才会被销毁。

首先，让我们来看这个例子：
```cpp
#include <iostream>
#include <string>

std::string getHello()
{
    return "Hello"; // 隐式转换为 std::string
}

int main()
{
    const std::string s{ getHello() };

    std::cout << s;

    return 0;
}
```

在这种情况下， `getHello()` 通过值返回一个 `std::string` ，这是一个右值。然后这个右值被用来初始化 `s` 。在 `s` 初始化完成后，创建右值的表达式的求值已经结束，右值被销毁。

现在让我们来看这个类似的例子：
```cpp
#include <iostream>
#include <string>

const std::string& foo(const std::string& s)
{
    return s;
}

std::string getHello()
{
    return "Hello"; // 隐式转换为 std::string
}

int main()
{
    const std::string s{ foo(getHello()) };

    std::cout << s;

    return 0;
}
```

这种情况下的唯一区别是，右值通过常量引用传递给 `foo()` ，然后在使用它来初始化 `s` 之前，通过常量引用返回给调用者。其他方面都完全相同。

#### 调用者可以通过引用修改值

当通过非常量引用传递参数给函数时，函数可以使用引用来修改参数的值。

类似地，当函数通过非常量引用返回值时，调用者可以使用引用来修改返回的值。

这里有一个说明性的例子：
```cpp
#include <iostream>

// 通过非常量引用接收两个整数，并返回较大者的引用
int& max(int& x, int& y)
{
    return (x > y) ? x : y;
}

int main()
{
    int a{ 5 };
    int b{ 6 };

    max(a, b) = 7; // 将 a 或 b 中较大的那个设为 7

    std::cout << a << b << '\n';

    return 0;
}
```

在上述程序中， `max(a, b)` 调用 `max()` 函数，并将 `a` 和 `b` 作为参数。引用参数 `x` 绑定到参数 `a` ，引用参数 `y` 绑定到参数 `b` 。然后函数确定 `x` ( `5` ) 和 `y` ( `6` ) 中哪个更大。在这种情况下，是 `y` ，所以函数返回 `y` （它仍然绑定到 `b` ）给调用者。调用者然后将值 `7` 赋给这个返回的引用。

因此，表达式 `max(a, b) = 7` 实际上解析为 `b = 7` 。

这段代码输出：
<pre>
57
</pre>
#### 通过地址返回

按地址返回几乎与按引用返回完全相同，只是返回的是对象的指针而不是对象的引用。按地址返回与按引用返回有相同的注意事项——通过地址返回的对象必须比返回地址的函数的作用域生存期更长，否则调用者将收到一个悬空指针。

通过地址返回的主要优势在于，如果没有任何有效的对象可以返回，函数可以返回 `nullptr` 。例如，假设我们有一组学生，想要在其中进行搜索。如果我们找到了我们想要的学生，我们可以返回一个指向代表匹配学生的对象的指针。如果我们没有找到任何匹配的学生，我们可以返回 `nullptr` 来表示没有找到匹配的学生对象。

返回地址的主要缺点是调用者必须记得在解引用返回值之前进行 `nullptr` 检查，否则可能会发生空指针解引用，导致未定义行为。由于这种危险，除非需要返回“无对象”的能力，否则应优先选择返回引用而不是返回地址。

> [!SUCCESS] 最佳实践
> 除非返回“无对象”（使用 `nullptr` ）的能力很重要，否则优先选择引用返回而不是地址返回。

### 输入和输出参数

函数与其调用者通过两种机制进行通信：参数和返回值。当函数被调用时，调用者提供参数，函数通过其参数接收这些参数。这些参数可以通过值、引用或地址传递。

通常，我们会通过值或常量引用传递参数。但有时我们可能需要以其他方式传递。

#### 输入参数

在大多数情况下，函数参数仅用于接收调用者的输入。仅用于接收调用者输入的参数有时被称为输入参数。
```cpp
#include <iostream>

void print(int x) // x 是输入参数
{
    std::cout << x << '\n';
}

void print(const std::string& s) // s 是输入参数
{
    std::cout << s << '\n';
}

int main()
{
    print(5);
    std::string s { "Hello, world!" };
    print(s);

    return 0;
}
```

输入参数通常通过值传递或通过常量引用传递。

#### 输出参数

通过非常量引用（或通过指向非常量的指针）传递的函数参数允许函数修改作为参数传递的对象的值。这为函数提供了一种在某种原因下使用返回值不足以返回数据给调用者的情况下的返回数据的方式。

一个仅用于将信息返回给调用者的函数参数称为输出参数。

例如:
```cpp
#include <cmath>    // 用于 std::sin() 和 std::cos()
#include <iostream>

// sinOut 和 cosOut 是输出参数
void getSinCos(double degrees, double& sinOut, double& cosOut)
{
    // sin() 和 cos() 使用弧度，需要进行转换
    constexpr double pi { 3.14159265358979323846 }; // π 的值
    double radians = degrees * pi / 180.0;
    sinOut = std::sin(radians);
    cosOut = std::cos(radians);
}

int main()
{
    double sin { 0.0 };
    double cos { 0.0 };

    double degrees{};
    std::cout << "请输入角度: ";
    std::cin >> degrees;

    // getSinCos 会把 sin 和 cos 写入对应变量
    getSinCos(degrees, sin, cos);

    std::cout << "sin 为 " << sin << '\n';
    std::cout << "cos 为 " << cos << '\n';

    return 0;
}
```

这个函数有一个输入参数 `degrees` （其参数按值传递），并作为输出返回两个参数（按引用）。

我们用后缀“out”来命名这些输出参数，以表明它们是输出参数。这有助于提醒调用者传递给这些参数的初始值并不重要，我们应该预期它们会被覆盖。按照惯例，*输出参数通常是参数列表中最右边的参数*。

让我们更详细地探讨这是如何工作的。首先，主函数创建了局部变量 `sin` 和 `cos` 。这些变量通过引用（而不是按值）传递给函数 `getSinCos()` 。这意味着函数 `getSinCos()` 可以访问 `main()` 中的实际 `sin` 和 `cos` 变量，而不仅仅是副本。 `getSinCos()` 相应地通过引用 `sinOut` 和 `cosOut` 分别为 `sin` 和 `cos` 分配新值，这覆盖了 `sin` 和 `cos` 中的旧值。然后函数 `main()` 打印这些更新后的值。

如果 `sin` 和 `cos` 是以值传递而不是引用传递， `getSinCos()` 会改变 `sin` 和 `cos` 的副本，导致任何更改在函数结束时被丢弃。但因为 `sin` 和 `cos` 是以引用传递，对 `sin` 或 `cos` （通过引用）所做的任何更改都会在函数外部持续存在。因此，我们可以利用这种机制将值返回给调用者。

> [!CITE] 旁注
> [这个 StackOverflow 上的回答](https://stackoverflow.com/questions/8763398/why-is-it-illegal-to-take-the-address-of-an-rvalue-temporary/9779765#9779765)很有趣，解释了为什么非常量左值引用不允许绑定到右值/临时对象（由于隐式类型转换在与输出参数结合时会产生意外的行为）。

#### 输出参数有不自然的用法语法

输出参数虽然功能强大，但也有一些缺点。

首先，调用者必须实例化（并初始化）对象，并将它们作为参数传递，即使它不打算使用它们。这些对象必须能够被赋值，这意味着它们不能被声明为常量。

其次，因为调用者必须传入对象，这些值不能作为临时变量使用，也不容易在单个表达式中使用。

以下示例展示了这两种缺点：
```cpp
#include <iostream>

int getByValue()
{
    return 5;
}

void getByReference(int& x)
{
    x = 5;
}

int main()
{
    // 按值返回
    [[maybe_unused]] int x{ getByValue() }; // 可用于初始化对象
    std::cout << getByValue() << '\n';      // 可在表达式中使用临时返回值

    // 通过输出参数返回
    int y{};                // 必须先创建可赋值对象
    getByReference(y);      // 然后传入函数赋值
    std::cout << y << '\n'; // 之后才能使用该值

    return 0;
}
```

如您所见，使用输出参数的语法有点不自然。

#### 通过引用传递的输出参数不会明显地表明参数将被修改

当我们把函数的返回值赋给一个对象时，很明显对象的值被修改了：
```cpp
x = getByValue(); // 清楚表明 x 被修改
```

这样很好，因为它清楚地表明我们应该预期 `x` 的值会改变。

然而，让我们再次看看上面示例中对 `getSinCos()` 的函数调用：
```cpp
getSinCos(degrees, sin, cos);
```

从这个函数调用中无法明确看出 `degrees` 是一个输入参数，但 `sin` 和 `cos` 是输出参数。如果调用者没有意识到 `sin` 和 `cos` 将被修改，很可能会出现语义错误。

使用按地址传递代替按引用传递，在某些情况下可以通过要求调用者将对象的地址作为参数传递，使输出参数更加明显。

考虑以下示例：
```cpp
void foo1(int x);  // 按值传递
void foo2(int& x); // 按引用传递
void foo3(int* x); // 按地址传递

int main()
{
    int i{};

    foo1(i);  // 不能修改 i
    foo2(i);  // 可以修改 i（不明显）
    foo3(&i); // 可以修改 i

    int *ptr { &i };
    foo3(ptr); // 可以修改 i（不明显）

    return 0;
}
```

注意，在调用 `foo3(&i)` 时，我们必须传递 `&i` 而不是 `i` ，这有助于更清楚地表明我们应预期 `i` 将被修改。

然而，这并非万无一失，因为 `foo3(ptr)` 允许 `foo3()` 修改 `i` ，并且不需要调用者提供 `ptr` 的地址。

调用者还可能认为他们可以传入 `nullptr` 或空指针作为有效参数，尽管这是不被允许的。现在函数必须执行空指针检查和处理，这增加了更多的复杂性。这种对空指针处理的需求往往比坚持使用引用传递会引发更多问题。

由于所有这些原因，除非没有其他好的选择，否则应避免使用输出参数。

> [!SUCCESS] 最佳实践
> 避免使用输出参数（除非在极少数情况下没有更好的选择）。
> 
> 优先使用引用传递非可选的输出参数。

#### 输入/输出参数

在极少数情况下，函数会实际在覆盖其值之前使用输出参数的值。这种参数称为<font color="#4dfe50">输入输出参数</font>(**in-out parameter**)。输入输出参数与输出参数工作方式完全相同，并具有所有相同的问题。

#### 什么时候通过非常量引用传递

如果你打算通过引用传递以避免复制参数，那么几乎总是应该通过常量引用传递。

> [!CITE] 作者注
> 在以下示例中，我们将使用 `Foo` 来表示我们关心的某种类型。目前，你可以将 `Foo` 想象成你选择的某种类型的别名（例如 `std::string` ）。

然而，在两种主要情况下，通过非常量引用传递可能是更好的选择。

首先，当参数是输入输出参数时，使用非常量引用传递。因为我们已经传递了需要返回的对象，所以直接修改该对象通常更直接且性能更好。
```cpp
void someFcn(Foo& inout)
{
    // 修改 inout
}

int main()
{
    Foo foo{};
    someFcn(foo); // foo 在调用后被修改，可能不够直观

    return 0;
}
```

给函数起一个好名字可以有所帮助：
```cpp
void modifyFoo(Foo& inout)
{
    // 修改 inout
}

int main()
{
    Foo foo{};
    modifyFoo(foo); // foo 在调用后被修改，稍微更直观

    return 0;
}
```

另一种方法是通过值或常量引用传递对象（按照常规方式），然后通过值返回一个新对象，调用者可以将这个新对象重新赋值给原始对象：
```cpp
Foo someFcn(const Foo& in)
{
    Foo foo { in }; // 在此处复制
    // 修改 foo
    return foo;
}

int main()
{
    Foo foo{};
    foo = someFcn(foo); // 更直观地表明 foo 被修改，但这里又复制一次

    return 0;
}
```

这可以采用更传统的返回语法，但需要创建 2 个额外的副本（有时编译器可以优化掉其中一个副本）。

其次，当函数本应通过值返回对象给调用者，但复制该对象成本极高时，使用非常量引用传递。特别是当函数在性能关键代码段中被频繁调用时。
```cpp
void generateExpensiveFoo(Foo& out)
{
    // 修改 out
}

int main()
{
    Foo foo{};
    generateExpensiveFoo(foo); // foo 在调用后被修改

    return 0;
}
```

话虽如此，对象很少昂贵到需要采用非常规方法来返回这些对象。

### 指针、引用和常量的类型推导

我们可以使用 `auto` 关键字让编译器从初始化器中推导变量的类型：
```cpp
int main()
{
    int a { 5 };
    auto b { a }; // b 被推导为 int

    return 0;
}
```

我们还注意到，默认情况下，类型推导会从类型中丢弃常量限定符 `const` ：
```cpp
int main()
{
    const double a { 7.8 }; // a 的类型是 const double
    auto b { a };           // b 的类型是 double（丢弃 const）

    constexpr double c { 7.8 }; // c 的类型是 const double（constexpr 隐式应用 const）
    auto d { c };               // d 的类型是 double（丢弃 const）

    return 0;
}
```

通过在推导出的类型定义中添加 `const` （或 `constexpr` ）限定符，可以重新应用常量属性（或 `constexpr` ）：
```cpp
int main()
{
    double a { 7.8 };    // a 的类型是 double
    const auto b { a };  // b 的类型是 const double（应用 const）

    constexpr double c { 7.8 }; // c 的类型是 const double（constexpr 隐式应用 const）
    const auto d { c };         // d 是 const double（丢弃 const 后重新应用）
    constexpr auto e { c };     // e 是 constexpr double（丢弃 const 后重新应用 constexpr）

    return 0;
}
```

#### 类型推导会丢弃引用

除了丢弃 `const` 之外，类型推导也会丢弃引用：
```cpp
#include <string>

std::string& getRef(); // 返回引用的函数

int main()
{
    auto ref { getRef() }; // 类型被推导为 std::string（不是 std::string&）

    return 0;
}
```

在上面的例子中，变量 `ref` 正在使用类型推导。尽管函数 `getRef()` 返回一个 `std::string&` ，但引用限定符被丢弃，因此 `ref` 的类型被推导为 `std::string` 。

就像丢弃 `const` 一样，如果你希望推导的类型是引用，你可以在定义点重新应用引用：
```cpp
#include <string>

std::string& getRef(); // 返回引用的函数

int main()
{
    auto ref1 { getRef() };  // std::string（丢弃引用）
    auto& ref2 { getRef() }; // std::string&（丢弃引用后重新应用引用）

    return 0;
}
```

#### 顶级 const 和低级 const

一个<font color="#4dfe50">顶级 const</font> (**top-level const**) 是一个应用于对象本身的 const 限定符。例如：
```cpp
const int x;    // 此处 const 作用于 x，因此是顶级 const
int* const ptr; // 此处 const 作用于 ptr，因此是顶级 const
// 引用没有顶级 const 语法，因为它们隐式为顶级 const
```

相比之下，一个<font color="#4dfe50">低级 const</font> (**low-level const**)是一个应用于被引用或指向的对象的 const 限定符：
```cpp
const int& ref; // 此处 const 作用于被引用对象，因此是低级 const
const int* ptr; // 此处 const 作用于被指向对象，因此是低级 const
```

对常量值的引用总是低级常量。指针可以有顶级、低级或两者兼有的常量：
```cpp
const int* const ptr; // 左侧 const 为低级 const，右侧 const 为顶级 const
```

当我们说类型推导会丢弃 `const` 限定符时，它只会丢弃顶级 const。低级 const 不会被丢弃。我们很快就会看到这方面的例子。

#### 类型推导与常量引用

如果初始化器是常量引用，则首先丢弃引用（如果适用，则重新应用），然后从结果中丢弃任何顶层 const。
```cpp
#include <string>

const std::string& getConstRef(); // 返回常量引用的函数

int main()
{
    auto ref1{ getConstRef() }; // std::string（丢弃引用后，结果中的顶级 const 也被丢弃）

    return 0;
}
```

在上述示例中，由于 `getConstRef()` 返回一个 `const std::string&` ，首先丢弃引用，留下 `const std::string` 。这个 const 现在是一个顶级 const，因此也被丢弃，推导出的类型为 `std::string` 。

> [!NOTE] 洞察
> 丢弃引用可能会将低级 const 变为顶级 const： `const std::string&` 是低级 const，但丢弃引用后得到 `const std::string` ，它是顶级 const。

我们可以重新应用引用和/或 const：
```cpp
#include <string>

const std::string& getConstRef(); // 返回常量引用的函数

int main()
{
    auto ref1{ getConstRef() };        // std::string（丢弃引用与顶级 const）
    const auto ref2{ getConstRef() };  // const std::string（丢弃引用与 const 后重新应用 const）

    auto& ref3{ getConstRef() };       // const std::string&（丢弃引用后重新应用引用，低级 const 未被丢弃）
    const auto& ref4{ getConstRef() }; // const std::string&（丢弃引用后重新应用引用，低级 const 未被丢弃）

    return 0;
}
```

我们在之前的例子中已经涵盖了 `ref1` 的情况。对于 `ref2` ，这和 `ref1` 的情况类似，只是我们重新应用了 `const` 限定符，因此推导出的类型是 `const std::string` 。

使用 `ref3` 时情况会更有趣。通常情况下，引用会首先被丢弃，但由于我们重新应用了引用，它没有被丢弃。这意味着类型仍然是 `const std::string&` 。而且由于这个 const 是低级别的 const，它也没有被丢弃。因此推导出的类型是 `const std::string&` 。

`ref4` 的情况与 `ref3` 类似，只是我们又重新应用了 `const` 限定符。由于类型已经被推断为指向 const 的引用，我们在这里重新应用 `const` 是多余的。不过，使用 `const` 在这里可以明确地表明结果将是 const（而在 `ref3` 的情况下，结果的 const 属性是隐式的，不明显）。

> [!SUCCESS] 最佳实践
> 如果你想要一个常量引用，即使不严格必要，也要重新应用 `const` 限定符，因为这样做可以明确你的意图，并有助于防止错误。

#### 常量表达式引用呢？

`constexpr` 不是表达式类型的一部分，因此它不会被 `auto` 推导。

> [!WARNING] 提醒
> 当定义一个常量引用（例如 `const int&` ）时，const 修饰的是被引用的对象，而不是引用本身。
> 
> 当定义指向常量变量的 constexpr 引用（例如 `constexpr const int&` ）时，我们需要同时应用 `constexpr` （适用于引用）和 `const` （适用于被引用的类型）。

```cpp
#include <string_view>
#include <iostream>

constexpr std::string_view hello { "Hello" };   // 隐式为 const

constexpr const std::string_view& getConstRef() // 函数为 constexpr，返回 const std::string_view&
{
    return hello;
}

int main()
{
    auto ref1{ getConstRef() };                  // std::string_view（丢弃引用与顶级 const）
    constexpr auto ref2{ getConstRef() };        // constexpr const std::string_view（丢弃引用与顶级 const，应用 constexpr，隐式为 const）

    auto& ref3{ getConstRef() };                 // const std::string_view&（重新应用引用，低级 const 未被丢弃）
    constexpr const auto& ref4{ getConstRef() }; // constexpr const std::string_view&（重新应用引用，低级 const 未被丢弃，应用 constexpr）

    return 0;
}
```

#### 类型推导和指针

与引用不同，类型推导不会丢弃指针：
```cpp
#include <string>

std::string* getPtr(); // 返回指针的函数

int main()
{
    auto ptr1{ getPtr() }; // std::string*

    return 0;
}
```

我们也可以使用星号与指针类型推导（ `auto*` ）结合，以更清晰地表明推导出的类型是指针：
```cpp
#include <string>

std::string* getPtr(); // 返回指针的函数

int main()
{
    auto ptr1{ getPtr() };  // std::string*
    auto* ptr2{ getPtr() }; // std::string*

    return 0;
}
```

> [!NOTE] 洞察
> 引用在类型推导过程中会被丢弃，而指针不会，这是因为引用和指针具有不同的语义。
> 
> 
> 当我们评估一个引用时，我们实际上是在评估被引用的对象。因此，在推断类型时，推断被引用对象的类型而不是引用本身是有道理的。此外，由于我们推断的是非引用类型，通过使用 `auto&` 很容易将其转换为引用。如果类型推断改为推断引用，如果我们不想要引用，那么移除引用的语法会复杂得多。
> 
> 
> 另一方面，指针持有对象的地址。当我们评估一个指针时，我们评估的是指针本身，而不是被指向的对象（如果我们想要评估被指向的对象，我们可以对指针进行解引用）。因此，推断指针的类型而不是被指向的对象的类型是有道理的。

#### auto 和 auto\*的区别 ==optional==

当我们使用 `auto` 与指针类型初始化器一起时，为 `auto` 推导的类型包括指针。所以对于上面的 `ptr1` ，替代 `auto` 的类型是 `std::string*` 。

当我们在指针类型初始化器中使用 `auto*` 时，auto 推导的类型不包括指针——类型推导完成后指针会重新应用。因此，对于上面的 `ptr2` ，用于替换 `auto` 的类型是 `std::string` ，然后指针会重新应用。

在大多数情况下，实际效果是相同的（在上面的例子中， `ptr1` 和 `ptr2` 都推导为 `std::string*` ）。

然而，在实践中有 `auto` 和 `auto*` 之间的几个区别。首先， `auto*` 必须解析为指针初始化器，否则将导致编译错误：
```cpp
#include <string>

std::string* getPtr(); // 返回指针的函数

int main()
{
    auto ptr3{ *getPtr() };      // std::string（因为对 getPtr() 做了解引用）
    auto* ptr4{ *getPtr() };     // 无法编译（初始化器不是指针）

    return 0;
}
```

这样解释是合理的：在 `ptr4` 的情况下， `auto` 推导为 `std::string` ，然后将指针重新应用。因此 `ptr4` 的类型是 `std::string*` ，我们不能用不是指针的初始化器来初始化 `std::string*` 。

其次，当我们引入 `const` 时， `auto` 和 `auto*` 的行为方式存在差异。我们将在下文中进行说明。

#### 类型推导与常量指针 ==optional==

由于指针不会被丢弃，我们不必担心这一点。但使用指针时，我们需要考虑常量指针和指向常量的指针这两种情况，同时还有 `auto` 与 `auto*` 的区别。就像引用一样，在指针类型推导过程中，只有顶层的 const 会被丢弃。

让我们从一个简单的例子开始：
```cpp
#include <string>

std::string* getPtr(); // 返回指针的函数

int main()
{
    const auto ptr1{ getPtr() };  // std::string* const
    auto const ptr2 { getPtr() }; // std::string* const

    const auto* ptr3{ getPtr() }; // const std::string*
    auto* const ptr4{ getPtr() }; // std::string* const

    return 0;
}
```

当我们使用 `auto const` 或 `const auto` 时，我们是在说，“将推导出的指针设为常量指针”。所以在 `ptr1` 和 `ptr2` 的情况下，推导出的类型是 `std::string*` ，然后应用 const，使得最终类型为 `std::string* const` 。这类似于 `const int` 和 `int const` 表示相同的意思。

然而，当我们使用 `auto*` 时，const 限定符的顺序很重要。一个 `const` 在左边表示“使推断出的指针成为指向常量的指针”，而一个 `const` 在右边表示“使推断出的指针类型成为常量指针”。因此 `ptr3` 最终成为指向常量的指针，而 `ptr4` 最终成为常量指针。

现在让我们来看一个初始化器是常量指针到常量的例子。
```cpp
#include <string>

int main()
{
    std::string s{};
    const std::string* const ptr { &s };

    auto ptr1{ ptr };  // const std::string*
    auto* ptr2{ ptr }; // const std::string*

    auto const ptr3{ ptr };  // const std::string* const
    const auto ptr4{ ptr };  // const std::string* const

    auto* const ptr5{ ptr }; // const std::string* const
    const auto* ptr6{ ptr }; // const std::string*

    const auto const ptr7{ ptr };  // 错误：const 限定符不能重复应用
    const auto* const ptr8{ ptr }; // const std::string* const

    return 0;
}
```

`ptr1` 和 `ptr2` 的情况很简单。最顶层的 const（指针本身的 const）被丢弃。指向的对象上的低层 const 没有被丢弃。所以在两种情况下，最终类型都是 `const std::string*` 。

`ptr3` 和 `ptr4` 的情况也很简单。顶层 const 被移除，但我们重新应用了它。指向的对象的低层 const 没有被移除。所以在两种情况下，最终类型都是 `const std::string* const` 。

`ptr5` 和 `ptr6` 的情况类似于我们之前示例中展示的情况。在这两种情况下，顶层的 const 都会被忽略。对于 `ptr5` ， `auto* const` 重新应用了顶层的 const，所以最终类型是 `const std::string* const` 。对于 `ptr6` ， `const auto*` 将 const 应用于所指向的类型（在这个例子中该类型已经是 const），所以最终类型是 `const std::string*` 。

在 `ptr7` 情况下，我们使用了两次 const 限定符，这是不允许的，会导致编译错误。

最后，在 `ptr8` 的情况下，我们在指针的两边都应用了 const（这是允许的，因为 `auto*` 必须是指针类型），所以结果类型是 `const std::string* const` 。

> [!SUCCESS] 最佳实践
> 如果你想要常量指针、指向常量的指针或指向常量的常量指针，即使不严格必要，也要重新应用 `const` 限定符，因为这样做可以明确你的意图并帮助防止错误。

> [!TIP] 提示
> 在推导指针类型时，考虑使用 `auto*` 。在这种情况下，使用 `auto*` 可以更清楚地表明我们在推导指针类型，借助编译器的帮助确保我们不会推导出非指针类型，并让你对 const 有更多的控制。

#### 摘要

很抱歉听到你头痛。我们快速回顾一下最重要的要点。

顶级 const 与低级 const：
- 顶级 const 适用于对象本身（例如 `const int x` 或 `int* const ptr` ）。
- 低级 const 适用于通过引用或指针访问的对象（例如 `const int& ref` ， `const int* ptr` ）。

类型推导推导的是什么：
- 类型推导首先会去掉任何引用（除非推导出的类型被定义为引用）。对于常量引用，去掉引用会导致（低层次的）const 变成顶级 const。
- 类型推导会丢弃任何顶层 const（除非推导出的类型定义为 `const` 或 `constexpr` ）。
- constexpr 不属于类型系统，因此永远不会被推导。它必须始终显式应用于推导出的类型。
- 类型推导不会丢弃指针。
- 始终显式将推导出的类型定义为引用、 `const` 或 `constexpr` （视情况而定），即使因为这些限定符是冗余的，因为它们会被推导出来。这有助于防止错误，并使你的意图更加明确。

类型推导与指针：
- 在使用 `auto` 时，只有当初始化器是指针时，推导出的类型才会是指针。在使用 `auto*` 时，无论初始化器是否是指针，推导出的类型始终是指针。
- `auto const` 和 `const auto` 都会使推导出的指针成为常量指针。没有方法可以使用 `auto` 显式指定低级 const（指向常量的指针）。
- `auto* const` 也会使推导出的指针成为常量指针。 `const auto*` 使推导出的指针成为指向常量的指针。如果这些难以记住， `int* const` 是常量指针（指向 int），所以 `auto* const` 必须是常量指针。 `const int*` 是指向常量的指针（int），所以 `const auto*` 必须是指向常量的指针。
- 在推导指针类型时，考虑使用 `auto*` 而不是 `auto` ，因为它允许你显式重新应用顶级和低级 const，并且如果未推导出指针类型将会报错。

### std::optional

考虑一个计算并返回值的函数：
```cpp
int doIntDivision(int x, int y)
{
    return x / y;
}
```

如果调用者传入一个语义上无效的值（例如 `y` = `0` ），这个函数无法计算一个值来返回（因为除以 0 在数学上未定义）。在这种情况下，我们该怎么办？由于计算结果的函数不应有任何副作用，这个函数无法合理地自行解决错误。在这种情况下，通常的做法是让函数检测错误，然后将错误传回给调用者，以某种程序适当的方式来处理。

在之前链接的课程中，我们介绍了两种让函数将错误返回给调用者的不同方法：
- 让返回类型为 void 的函数改为返回 bool（表示成功或失败）。
- 让一个返回值的函数返回一个哨兵值（一个特殊值，该值不会出现在函数通常可以返回的可能值集合中）来指示错误。

作为后者的一个例子，以下 `reciprocal()` 函数如果用户为 `x` 传递了一个语义上无效的参数，则返回值 `0.0` （该值在其他情况下永远不会出现）：
```cpp
#include <iostream>

// x 的倒数是 1/x，当 x=0 时返回 0.0
double reciprocal(double x)
{
    if (x == 0.0) // 如果 x 在语义上无效
       return 0.0; // 返回 0.0 作为哨兵值，表示发生错误

    return 1.0 / x;
}

void testReciprocal(double d)
{
     double result { reciprocal(d) };
     std::cout << d << " 的倒数是 ";
     if (result != 0.0)
         std::cout << result << '\n';
     else
         std::cout << "未定义\n";
}

int main()
{
    testReciprocal(5.0);
    testReciprocal(-4.0);
    testReciprocal(0.0);

    return 0;
}
```

虽然这是一个相当吸引人的解决方案，但存在一些潜在的缺点：
- 程序员必须知道函数使用哪个哨兵值来指示错误（并且这个值可能因每个使用此方法返回错误的函数而异）。
- 同一个函数的不同版本可能会使用不同的哨兵值。
- 这种方法不适用于所有可能的哨兵值都是有效返回值的函数。

考虑我们上面提到的 `doIntDivision()` 函数。如果用户为 `y` 传入 `0` ，它能返回什么值呢？我们不能使用 `0` ，因为 `0` 除以任何数都会得到 `0` 作为有效结果。事实上，没有我们返回的值是不能自然发生的。

那我们该怎么办呢？

首先，我们可以选择一个（希望是）不常见的返回值作为我们的哨兵值，并使用它来表示错误：
```cpp
#include <limits> // 用于 std::numeric_limits

// 失败时返回 std::numeric_limits<int>::lowest()
int doIntDivision(int x, int y)
{
    if (y == 0)
        return std::numeric_limits<int>::lowest();
    return x / y;
}
```

`std::numeric_limits<T>::lowest()` 是一个返回类型 `T` 的最负值的功能。它是 `std::numeric_limits<T>::max()` 函数的对应函数（该函数返回类型 `T` 的最大正值）。

在上面的示例中，如果 `doIntDivision()` 无法继续执行，我们返回 `std::numeric_limits<int>::lowest()` ，它将最负的 int 值返回给调用者，以表示函数失败。

虽然这种方法基本可行，但它有两个缺点：
- 每次调用这个函数时，我们都需要测试返回值是否等于 `std::numeric_limits<int>::lowest()` ，以检查是否失败。这很冗长且难看。
- 这是一个半谓词问题的例子：如果用户调用 `doIntDivision(std::numeric_limits<int>::lowest(), 1)` ，返回的结果 `std::numeric_limits<int>::lowest()` 将无法明确判断函数是否成功或失败。这可能是也可能不是问题，具体取决于函数的实际使用方式，但它又是我们必须考虑的另一个问题，也是错误可能侵入我们程序的另一个潜在途径。

其次，我们可以放弃使用返回值来返回错误，转而使用其他机制（例如异常）。然而，异常有其自身的复杂性和性能开销，可能并不合适或所需。对于这种情况，这可能有点过度了。

第三，我们可以放弃返回单个值，而是返回两个值：一个（类型为 `bool` ）指示函数是否成功，另一个（所需返回类型的值）持有实际返回值（如果函数成功）或不确定的值（如果函数失败）。这可能是这几个选项中最好的选择。

在 C++17 之前，选择这种后一种选项需要你自行实现。而尽管 C++提供了多种实现方式，但任何自行开发的方法都不可避免地会导致不一致和错误。

#### 返回一个 `std::optional`

C++17 引入了 `std::optional` ，它是一个类模板类型，用于实现可选值。也就是说，一个 `std::optional<T>` 要么有一个类型为 `T` 的值，要么没有值。我们可以用这个来实现在上面的第三种情况：
```cpp
#include <iostream>
#include <optional> // 用于 std::optional（C++17）

// 函数现在可选地返回一个 int 值
std::optional<int> doIntDivision(int x, int y)
{
    if (y == 0)
        return {}; // 或返回 std::nullopt
    return x / y;
}

int main()
{
    std::optional<int> result1 { doIntDivision(20, 5) };
    if (result1) // 如果函数返回了值
        std::cout << "结果 1: " << *result1 << '\n'; // 获取值
    else
        std::cout << "结果 1: 失败\n";

    std::optional<int> result2 { doIntDivision(5, 0) };

    if (result2)
        std::cout << "结果 2: " << *result2 << '\n';
    else
        std::cout << "结果 2: 失败\n";

    return 0;
}
```

这段代码输出：
<pre>
结果 1: 4
结果 2: 失败
</pre>

使用 `std::optional` 非常简单。我们可以带值或不带值地构造一个 `std::optional<T>` ：
```cpp
std::optional<int> o1 { 5 };            // 用一个值初始化
std::optional<int> o2 {};               // 初始化为无值
std::optional<int> o3 { std::nullopt }; // 初始化为无值
```

要检查一个 `std::optional` 是否有值，我们可以选择以下方式之一：
```cpp
if (o1.has_value()) // 调用 has_value() 检查 o1 是否有值
if (o2)             // 使用隐式 bool 转换检查 o2 是否有值
```

要从 `std::optional` 获取值，我们可以选择以下方式之一：
```cpp
std::cout << *o1;             // 解引用以获取 o1 中存储的值（若 o1 无值则为未定义行为）
std::cout << o2.value();      // 调用 value() 获取 o2 的值（若 o2 无值会抛出 std::bad_optional_access 异常）
std::cout << o3.value_or(42); // 调用 value_or() 获取 o3 的值（若无值则返回 42）
```

注意 `std::optional` 的使用语法与指针基本上是相同的：

| 行为     | 指针                           | std::optional                |
| ------ | ---------------------------- | ---------------------------- |
| 不持有任何值 | 初始化/赋值 `{}` 或 `std::nullptr` | 初始化/赋值 `{}` 或 `std::nullopt` |
| 持有值    | 初始化/赋值一个地址                   | 初始化/赋值一个值                    |
| 检查是否有值 | 隐式转换为 bool                   | 隐式转换为 bool 或 `has_value()`   |
| 获取值    | 解引用                          | 解引用或 `value()`               |

然而，从语义上讲，指针和 `std::optional` 有很大的不同。
- 一个指针具有引用语义，这意味着它引用了另一个对象，而赋值操作复制的是指针，而不是对象。如果我们通过地址返回一个指针，那么返回到调用者的只是指针的副本，而不是被指向的对象。这意味着我们不能通过地址返回一个局部对象，因为我们会将那个对象的地址复制回调用者，然后该对象将被销毁，导致返回的指针悬空。
- 一个 `std::optional` 具有值语义，这意味着它实际包含其值，赋值会复制该值。如果我们通过值返回一个 `std::optional` ，则 `std::optional` （包括包含的值）会被复制回调用者。这意味着我们可以使用 `std::optional` 将值从函数返回给调用者。

考虑到这一点，让我们看看我们的示例是如何工作的。我们的 `doIntDivision()` 现在返回一个 `std::optional<int>` 而不是 `int` 。在函数体内，如果我们检测到错误，我们返回 `{}` ，这会隐式地返回一个不包含值的 `std::optional` 。如果我们有值，我们返回那个值，这会隐式地返回一个包含那个值的 `std::optional` 。

在 `main()` 中，我们使用隐式转换为 bool 来检查我们返回的 `std::optional` 是否有值。如果有，我们解引用 `std::optional` 对象来获取值。如果没有，则执行我们的错误条件。就这样！

#### 返回 `std::optional` 的优缺点

返回 `std::optional` 有诸多好处：
- 使用 `std::optional` 有效地说明了函数可能会返回值或不会返回值。
- 我们不必记住哪个值作为哨兵返回。
- 使用 `std::optional` 的语法方便且直观。

返回 `std::optional` 确实有几个缺点：
- 我们必须确保在获取值之前 `std::optional` 包含一个值。如果我们对一个不包含值的 `std::optional` 进行解引用，我们会得到未定义行为。
- `std::optional` 没有提供一种返回函数失败原因信息的方式。

除非你的函数需要返回关于失败原因的额外信息（无论是为了更好地理解失败，还是为了区分不同类型的失败），对于可能返回值或失败的函数， `std::optional` 是一个极好的选择。

> [!SUCCESS] 最佳实践
> 对于可能失败的函数，返回 `std::optional` （而不是哨兵值），除非你的函数需要返回关于失败原因的额外信息。

#### 使用 `std::optional` 作为可选函数参数

在上文中，我们讨论了如何使用按地址传递来允许函数接受一个“可选”参数（也就是说，调用者可以传递 `nullptr` 来表示“没有参数”或传递一个对象）。然而，这种方法的缺点是，非空指针参数必须是左值（以便其地址可以传递给函数）。

或许并不令人意外（考虑到其名称）， `std::optional` 是函数接受可选参数的一种替代方式（该参数仅用作输入参数）。而不是这样：
```cpp
#include <iostream>

void printIDNumber(const int *id=nullptr)
{
    if (id)
        std::cout << "你的 ID 号是 " << *id << ".\n";
    else
        std::cout << "你的 ID 号未知。\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(&userid); // 我们现在知道用户的 ID

    return 0;
}
```

你可以这样做：
```cpp
#include <iostream>
#include <optional>

void printIDNumber(std::optional<const int> id = std::nullopt)
{
    if (id)
        std::cout << "你的 ID 号是 " << *id << ".\n";
    else
        std::cout << "你的 ID 号未知。\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(userid); // 我们现在知道用户的 ID

    printIDNumber(62); // 也可以传入右值

    return 0;
}
```

这种方法有两个优点：
- 它有效地记录了参数是可选的。
- 我们可以传入一个右值（因为 `std::optional` 会创建一个副本）。

然而，因为 `std::optional` 会复制它的参数，当 `T` 是一个复制成本高昂的类型（比如 `std::string` ）时，这就变得有问题了。对于普通的函数参数，我们通过将参数设为常量左值引用（`const lvalue reference`）来解决这个问题，这样就不会创建副本。不幸的是，截至 C++23， `std::optional` 不支持引用。

因此，我们建议仅在 `T` 通常按值传递时使用 `std::optional<T>` 作为可选参数。否则，使用 `const T*` 。

---
##### 对于高级读者 ==optional==

尽管 `std::optional` 不直接支持引用，但你可以使用 `std::reference_wrapper` 来模拟引用。让我们看看使用 `std::string` id 和 `std::reference_wrapper` 时上述程序的样子：
```cpp
#include <functional>  // 用于 std::reference_wrapper
#include <iostream>
#include <optional>
#include <string>

struct Employee
{
    std::string name{}; // 复制成本高
    int id;
};

void printEmployeeID(std::optional<std::reference_wrapper<Employee>> e=std::nullopt)
{
    if (e)
        std::cout << "你的 ID 号是 " << e->get().id << ".\n";
    else
        std::cout << "你的 ID 号未知。\n";
}

int main()
{
    printEmployeeID(); // 我们还不知道 Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // 我们现在知道 Employee 的 ID

    return 0;
}
```

这两个程序几乎完全相同。我们会认为前者并不比后者更易读或更易于维护，也不值得为了引入两个额外的类型而将其添加到你的程序中。

---

在许多情况下，函数重载提供了一个更优越的解决方案：
```cpp
#include <iostream>
#include <string>

struct Employee
{
    std::string name{}; // 复制成本高
    int id;
};

void printEmployeeID()
{
    std::cout << "Your ID number is not known.\n";
}

void printEmployeeID(const Employee& e)
{
    std::cout << "你的 ID 号是 " << e.id << ".\n";
}

int main()
{
    printEmployeeID(); // 我们还不知道 Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // 我们现在知道 Employee 的 ID

    printEmployeeID( { "Dave", 62 } ); // 甚至可以传入右值

    return 0;
}
```

> [!SUCCESS] 最佳实践
> 推荐使用 `std::optional` 作为可选返回类型。
> 
> 推荐使用函数重载处理可选函数参数（在可能的情况下）。否则，当 `T` 通常按值传递时，使用 `std::optional<T>` 作为可选参数。当 `T` 复制成本较高时，优先使用 `const T*` 。
